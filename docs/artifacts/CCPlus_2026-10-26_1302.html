What's New

Auto mode, permissions & sandbox

  • /auto-mode-setup on third-party providers (v2.1.304). The guided setup, which reads your project and recent sessions to draft autoMode.environment entries and writes them to ~/.claude/settings.json if you accept, now also runs on Bedrock, Vertex, Foundry, the Claude apps gateway and telemetry-disabled sessions. The command itself already existed on first-party plans; the auto-mode docs list v2.1.304 as the minimum for these session types. [1][8]
  • sed -i gets a normal Bash prompt (v2.1.309). It now runs as written after the standard Bash permission prompt rather than showing a simulated file-edit preview. Like other Bash edits, it is no longer restored by /rewind. [6]
  • claude ultrareview requires workspace trust (v2.1.309). It asks on a terminal and refuses otherwise. Scripts can pass --trust-workspace (it takes no value, so put a PR number or base branch before it) or set CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1. [6]
  • Nested user namespaces in the Linux sandbox (v2.1.305). The new sandbox.allowNestedUserNamespaces setting lets sandboxed commands create user namespaces, which Chromium, Electron and rootless podman need. The release notes and sandboxing docs both warn that this lets sandboxed code get around the sandbox's file protections. The docs say to set it in ~/.claude/settings.json rather than project settings. [2][9]
  • Sandbox fallback is stricter (v2.1.309). When the sandbox is enabled but can't run, commands that settings exclude from the sandbox now ask before writing to its write-list paths, and the unsandboxed fallback is refused. On Linux, /sandbox and the startup warning now name Ubuntu's AppArmor user-namespace restriction and how to lift it when it stops bubblewrap (v2.1.310). [6][7]
  • Security fixes (v2.1.309–310). Sandboxed Bash on macOS and Linux no longer runs the shell's startup files outside the sandbox before each command. Sandboxed commands and auto-accepted edits can no longer modify the file passed with --mcp-config. macOS denyWrite globs now apply through symlinked folders, and an Edit(path) deny rule now blocks more Bash redirects. PowerShell hooks that exit with code 2 now block. On Windows, PreToolUse/PermissionRequest hooks no longer fail open when Git Bash or Git for Windows is missing. [6][7]
  • Dangerous rm in bypass mode on Desktop and VS Code (v2.1.309). The prompt now denies the command at once with a hint to rewrite it, so unattended sessions keep going. [6]
  • Settings-scope changes. axScreenReader and CLAUDE_AX_SCREEN_READER in a settings env block now apply only from user, managed or --settings settings (v2.1.307) [4]. allowedMcpServers no longer filters managed-mcp.json stdio servers that use ${VAR} only in env, so one your allowlist left out now loads; use deniedMcpServers to keep it off (v2.1.305). Under allowManagedPermissionRulesOnly, plugins that Claude Desktop mounts by path lose their allowed-tools (v2.1.305). [2]

Providers & gateways

  • Tool search on by default behind a custom ANTHROPIC_BASE_URL (v2.1.304). If the gateway answers 400 or 422, Claude Code retries without it. v2.1.305 fixed a v2.1.304 regression where every request failed on Vertex, Bedrock and other providers whose endpoint or gateway rejected tool search. [1][2]
  • Monitor on Bedrock, Vertex and Foundry (v2.1.310). The Monitor tool and plugin monitors are now available there and when telemetry or nonessential traffic is off. Long foreground sleeps are now blocked in those sessions too. [7]
  • Gateway compatibility retries. Claude Code now retries without the effort-2025-11-24 beta or mid-conversation system messages when a gateway rejects them (v2.1.310), and without context_management on "Extra inputs are not permitted" errors (v2.1.304). [7][1]

Context, skills & sessions

  • Skills after compaction (v2.1.304). Compaction now sends Claude the skill list again afterwards, and /reload-skills sends only new or changed skills. The skills of a single source (a repo, your own folder or a plugin) can register at most 1,024 hooks and 16,384 matcher characters per session. [1]
  • CLAUDE_CODE_AUTO_COMPACT_WINDOW accepts k/M (v2.1.304). Before this fix, 200k silently set a 100K window. The variable now takes the same suffixes as --autocompact and warns when a value is out of range or ignored. [1]
  • Resume-cost warning on Pro and Max (v2.1.304). Resuming an inactive conversation that would use a noticeable share of your 5-hour limit now warns you. You can resume anyway or start fresh and let Claude look up the old conversation if you refer to it. [1]
  • Large nested CLAUDE.md files (v2.1.309). A nested CLAUDE.md over the size limit now loads only its start, which fixes sessions that kept compacting after reading files under it. [6]
  • Agent reliability (v2.1.307). Unparseable tool calls are retried up to twice before the turn ends with an error. Forks launched together are each told which launch is theirs, so they are much less likely to pick up each other's work. [4]
  • Unattended retry recheck (v2.1.305). CLAUDE_CODE_RETRY_WATCHDOG_USAGE_LIMIT_RECHECK_MS lets unattended retry mode notice when a usage limit is lifted before its reset time. [2]

Observability, tooling & enterprise

  • claude_code.safety_event (v2.1.307). A new OpenTelemetry event fires for each tool call that a permission rule, auto mode, a safety check, a hook or the sandbox stopped, prompted or sent back. The monitoring docs say it needs no separate setting and carries no command text or paths; join it to tool_decision (with OTEL_LOG_TOOL_DETAILS=1) to see the command. [4][10]
  • /usage fixes (v2.1.305). Each /usage warning is now a one-line fix naming its source, and pressing f applies the fixes. The same fixes show in VS Code and /doctor. [2]
  • /claude-api additions. /claude-api managed-agents-secure compares a Managed Agents agent's settings with Anthropic's security guide without changing anything (v2.1.304) [1]. /claude-api api-version moves Claude API code to API version 2026-10-21 (v2.1.307) [4]. Managed Agents subagent teams are now built on multiagent_20261001 with dynamic workflows on by default (v2.1.309). [6]
  • Mods API (v2.1.304). A mod's tool.check can answer decider: "person" so only a human can approve, and its event now has e.isReadOnly. settings.read hooks receive each settings layer, so a managed mod can make an organization setting a ceiling. [1]
  • Code Review (GitHub app). Owners can choose Quick, Standard (default) or Deep review levels per organization or repository, and can review every repository in a GitHub org (v2.1.304) [1]. @claude review stop (also off/pause) ends an @claude review always subscription (v2.1.307). [4]
  • Self-hosted runner checkout hooks (v2.1.307). They are now stopped after 30 minutes by default, failing setup; raise --checkout-hook-timeout-min or set it to 0. [4]
  • Enterprise custom roles (v2.1.310). Cloud sessions and Remote Control permissions can now be granted per custom role, and turning either on in admin settings asks for confirmation. [7]
  • Misc. /fast on Opus 5.5 no longer carries a "(research preview)" label (v2.1.304) [1]; the /artifacts delete confirmation now uses 1/Enter to keep and 2 to delete (v2.1.304–305) [1][2]; worktree creation no longer fetches git objects on demand (v2.1.309). [6]

Tips & Techniques

  • Check your autocompact window value. If you set CLAUDE_CODE_AUTO_COMPACT_WINDOW with a k suffix before v2.1.304, you were getting 100K. Upgrade and confirm the warning is gone. [1]
  • Run /auto-mode-setup on Bedrock, Vertex or Foundry. It drafts the autoMode.environment entries that stop routine internal pushes and bucket writes from being blocked. Run claude auto-mode config afterwards to check the result. [1][8]
  • Commit before letting Claude run sed -i. These edits are no longer undone by /rewind, so git is your safety net. [6]
  • Build a block dashboard from safety_event. Counting events by category and rule_source shows which rules or classifier categories cause the most friction. [10]
  • Try f in /usage. Each warning is now a one-line fix that names its source, and f applies them. [2]

Recommended Default-Config Changes

  • Re-check MCP allowlists. If you relied on allowedMcpServers to keep a managed-mcp.json stdio server off, and it uses ${VAR} only in env, add it to deniedMcpServers. It will otherwise load after upgrading. [2]
  • Update scripts that call claude ultrareview. Add --trust-workspace after the PR number or base branch, or set CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1 in trusted CI only. [6]
  • Keep sandbox.allowNestedUserNamespaces off unless you need it. Turn it on only for Chromium, Electron or rootless podman workflows, in user settings, and with your security team's sign-off. [2][9]
  • Move screen-reader settings. If axScreenReader or CLAUDE_AX_SCREEN_READER lives in project settings, move it to ~/.claude/settings.json. [4]
  • Self-hosted runners: set --checkout-hook-timeout-min if a checkout hook needs more than 30 minutes. [4]
  • Gateways: tool search is now on behind custom base URLs. If your gateway blocks it, upgrade to at least v2.1.305 to get the automatic retry fix. [1][2]
