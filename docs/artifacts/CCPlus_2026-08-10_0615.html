Summary

The short window since v1.1 (Aug 6) was quieter and infrastructure-focused — no new models or default-model changes — but three releases (v2.1.224–v2.1.226) still landed several things worth acting on[1]. The headline is self-hosted runners: claude self-hosted-runner turns your own machines or containers into a place Claude Code web, mobile, and desktop sessions can run, on Team and Enterprise plans[2]. New configuration surfaces arrived too: an archive plugin source (install from a zip over HTTPS with optional SHA-256 pinning)[2][6], the crossSessionInbound and dialogExpiry settings[5], a ANTHROPIC_BEDROCK_REGION_PREFIX env var, and richer sandbox credential-masking[2]. The current CLI is v2.1.226 (Aug 8)[1]. Every claim below is cited; sources are listed at the bottom.

What's New

Highlights from Claude Code CLI v2.1.224 → v2.1.226 (August 7–8, 2026)[1].

  • Self-hosted runners (v2.1.224, Aug 7). claude self-hosted-runner turns your own machines or containers into a place Claude Code web, mobile, and desktop sessions can run, on Team and Enterprise plans. It exits at startup with a clear error if --base-dir cannot be created or written (v2.1.225)[2][3].
  • Sessions can message each other (v2.1.224, Aug 7). Cross-session SendMessage lets Claude Code sessions message one another across any of your machines, with ListAgents to discover them (macOS and Linux). In v2.1.225, SendMessage can also start a conversation with your Remote Control sessions on other machines by name (ListAgents shows them as name [ref]), instead of only replying after they message you first[2][3].
  • archive plugin source (v2.1.224, Aug 7) — install plugins from a zip over HTTPS without git or npm, with optional SHA-256 pinning. This complements the existing zip support in the docs: --plugin-dir ./my-plugin.zip loads a local archive, and --plugin-url https://…/my-plugin.zip fetches one at startup for that session only[2][6].
  • Sandbox credential-masking options (v2.1.224, Aug 7) — new extract / onExtractNoMatch handling for structured env values, decode: "jwt" with maskClaims for JWT-aware masking, and awsPairs / sigv4 for AWS SigV4 re-signing. These require network.tlsTerminate and are honored only from user, managed, or --settings settings[2].
  • Workspace-trust prompt for claude agents (v2.1.225, Aug 8) — launching claude agents in an untrusted directory now shows a trust prompt, matching the behavior of claude[3].
  • Gateway spend-limit awareness (v2.1.225, Aug 8) — Claude Code's usage warning now names the cap, its reset time, and the operator's message when a gateway spend-limit is hit (requires the gateway on 2.1.225)[3].
  • The 200-subagent-per-session spawn cap was removed (v2.1.224, Aug 7) — long-running sessions no longer refuse new agents; concurrency and depth limits still apply. This supersedes the v1.1 note that a per-session cap of 200 (CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION) was in effect[2].
  • Feedback-survey share now includes model settings (with consent) (v2.1.224, Aug 7) — the survey's transcript share can now also upload the last request's model settings: the system prompt (which includes your CLAUDE.md instructions), tool definitions, and model parameters. Secrets are redacted as before, and these fields are dropped first if the share is too large[2].
  • v2.1.226 is a bug-fix / reliability release (Aug 8) — no new features, defaults, or flags[4].

Tips & Techniques

  • Control what other sessions can send you with crossSessionInbound (v2.1.224): "accept" delivers inbound messages to Claude, "hold" shows a notice per message without delivering it, and "refuse" drops them. Pair it with dialogExpiry (default "5m"; accepts "60s", "5m", "10m", or "never") to bound how long held messages and forwarded dialogs wait before Claude falls back to its no-action default[5].
  • Pin a Bedrock cross-region inference profile with the new ANTHROPIC_BEDROCK_REGION_PREFIX env var, which is preferred over the AWS_REGION-derived one (v2.1.224)[2].
  • Fullscreen mode keeps your full history. After v2.1.224, fullscreen mode retains the full pre-compaction history in scrollback across repeated compactions, instead of only the most recent interval[2].
  • Remember Bash output goes to the model, not the user. The Bash tool description now always notes that command output is displayed to the model and not reliably to the user — surface anything the human needs to see in your reply, not just in a command's output (v2.1.224)[2].

Hacks

Lesser-known but documented power-user techniques (each corroborated by the release notes and docs).

  • Ship a plugin straight from a CI artifact. Point --plugin-url at a hosted .zip to load a plugin for one session, or use the archive source to install one over HTTPS — no git or npm required[2][6].
  • Pin plugin integrity with SHA-256. The archive plugin source supports optional SHA-256 pinning, so a zip that changes upstream won't silently swap what you install[2].
  • Quarantine a bypassed-permissions session's inbox. Set "crossSessionInbound": "hold" (or "refuse") so messages sent to a session running with bypassed permissions are held for your approval rather than acted on automatically[5][2].

Recommended Default-Config Changes

Nothing this period forces a change to the v1.1 starter settings.json (models and permission defaults are unchanged). The new keys are opt-in and mostly matter if you use cross-session messaging, Remote Control, or self-hosted runners. On a managed/Enterprise machine, managed settings take precedence[5].

{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "opusplan",
  "effortLevel": "high",
  "crossSessionInbound": "hold",
  "dialogExpiry": "5m"
}

What's new here vs v1.1: crossSessionInbound and dialogExpiry both require CLI v2.1.224+. crossSessionInbound follows a precedence of managed → --settings → user → per-message defaults (project/local apply only when stricter); dialogExpiry is read from user, managed, and --settings sources only, and can be overridden per-session with CLAUDE_CODE_USER_DIALOG_TIMEOUT_MS[5].

If you run cross-session or self-hosted setups

  • Set an inbox posture deliberately. The default is session-class-dependent: bypassed-permission sessions hold inbound messages automatically, while other sessions auto-deliver. Set "hold" explicitly for any unattended session so the behavior is stable regardless of permission state[5].
  • Prefer pinned plugin sources. When installing via the archive source, add the SHA-256 pin so builds are reproducible and tamper-evident[2].
  • For Bedrock, set ANTHROPIC_BEDROCK_REGION_PREFIX if you need a specific cross-region inference profile rather than the one derived from AWS_REGION[2].

Good habits

  • Keep the CLI current — v2.1.226 is the latest and includes reliability fixes; recent releases also hardened sandbox deny-rules and cross-session delivery error reporting[1][2].
  • Treat cross-session messages as untrusted input: hold or refuse them for privileged sessions, and rely on the new claude agents workspace-trust prompt in unfamiliar directories[5][3].
  • Remember that a feedback-survey share can now upload your system prompt (including CLAUDE.md), tool definitions, and model parameters — review before consenting if those contain anything sensitive[2].
