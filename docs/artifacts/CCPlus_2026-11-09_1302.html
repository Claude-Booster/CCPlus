What's New

Auto mode & permissions

  • No silent classifier fallback (v2.1.319). With telemetry or feature flags off, including behind LLM gateways, auto mode now asks about or denies calls the server-side check can't review. It no longer falls back to the built-in classifier. Set CLAUDE_CODE_AUTO_MODE_SERVER=0 to keep the classifier. Bedrock, Vertex and Foundry are unchanged. [3][6]
  • Gateway server check (v2.1.319). Behind an LLM gateway, CLAUDE_CODE_AUTO_MODE_SERVER=1 turns on the server-side check even when CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS is set. If managed settings set the latter, they must also set the 1. A project's settings files or a plugin can no longer turn the server check back on after you have turned it off outside the project. /status no longer says "Auto mode server: Enabled" when the review isn't reaching the session. [3]
  • permissions.denyInsteadOfPrompting (v2.1.319). A tool call that would wait on a permission prompt is denied, and the turn continues. It applies in terminal sessions, subagents and teammates. The settings reference doesn't list it yet. [3]
  • Exit codes in auto mode (v2.1.319). claude -p now exits 1, in text and JSON output, when auto mode refused actions because no safety check was available. Before, it exited 0. [3]
  • Rule changes (v2.1.319). A session's exact Bash or PowerShell ask rule is now refused, not asked about, when a broader deny rule covers the command. Bash asks before running which with flags outside a lookup/display set. Monitor's WebSocket watch now follows Bash rules. Bash deny and ask rules now catch commands written with quoted words. A plain timeout DURATION wrapper around a read-only command, such as timeout 30 rg foo, no longer prompts. [3]
  • Security fixes (v2.1.319). A Bash permission bypass using a crafted environment prefix; a sed command skipping the permission check in accept-edits and auto mode; a sandbox escape when creating a worktree; and /rewind restoring or deleting a file through a directory symlink. On self-hosted runners, --trust-workspace false now also stops repository hooks and skills from running. [3]
  • Trust and nested skills (v2.1.319). --add-dir directories register plugin marketplaces only after that directory's trust dialog is accepted. With the Bash sandbox on, skills in .claude/skills folders below the starting folder load only if you start or /cd there. CLAUDE_CODE_PROXY_RESOLVES_HOSTS can no longer be set from settings files where the host manages the network. [3]
  • deniedMcpServers URL entries (v2.1.318). They now also block Anthropic-provided servers whose upstream URL matches. They also block connectors in cloud sessions and on self-hosted runners; elsewhere, deny a connector by name. [2]
  • Email-address check (v2.1.317). Claude Code now asks before a web or shell tool call sends your account email address to the network. /schedule warns when a new cloud scheduled task gets connectors you didn't ask for. [1]

Agents, effort & loops

  • Per-model effort for subagents (v2.1.317). Subagents and teammates on a different model from the main conversation now use that model's saved effort level or its default, not the session's. [1]
  • Self-paced /loop ends on its own (v2.1.319). When a turn finishes without rescheduling, the loop ends instead of scheduling a fallback wakeup. Set CLAUDE_CODE_LOOP_KEEPALIVE=1 for the old behavior. In cloud sessions, /loop confirmations now note that a timer stops with its container. [3]
  • Finished subagents in /tasks (v2.1.319). An "Earlier in this session" row lists finished subagents, so you can reopen and message one after it leaves the list or after a restart. /clear no longer kills running commands of background agents, teammates and workflows. [3]
  • SendMessage and background shells. A message to a running background agent now arrives sooner: its running command moves to the background without being stopped (v2.1.317) [1]. Background subagents move a shell command to the background after 3 minutes on all providers, so the prompt cache doesn't expire while it runs (v2.1.318). [2]
  • Mods. A mod's $.model.fork takes an effort option, for example to run a quick side job at low (v2.1.318). What a mod attaches at prompt.submit now stays in the user's turn, not a system message. [2]
  • Agent SDK. Hook callbacks accept onFailure: "block", so a failing callback blocks the action instead of letting it run (v2.1.317). [1]

MCP & tools

  • MCP tasks in the terminal (v2.1.319). When an MCP server runs a tool call as a task, Claude Code moves it to the background right away and tells Claude the result when it finishes. CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND makes it wait inside the tool call instead, and CLAUDE_CODE_DISABLE_MCP_TASKS=1 turns MCP tasks off. MCP tasks also work without feature-flag fetching (Bedrock, Vertex, Foundry, gateways, DISABLE_TELEMETRY). [3][6]
  • MCP fixes. Servers on the older handshake no longer fail to connect or return empty results because Claude Code declared an extension it only uses with newer servers (v2.1.319) [3]. An MCP tool called before it loads now returns its input schema in the error (v2.1.318). [2]
  • Read returns content again (v2.1.317). The "file unchanged since your last Read" stub is gone; reading an unchanged file again returns its content. Claude also no longer treats Grep and Glob results that hit the time limit as complete. [1]
  • /context is cheaper (v2.1.319). It no longer sends its full visual grid to Claude on every later turn. Claude reads a short table instead, with the 10 largest rows per list. [3]
  • PostToolUse after interrupts (v2.1.319). These hooks now run, with up to 10 seconds, on tool calls that finish after a new message interrupts the turn. [3]
  • /claude-api latency-optimize (v2.1.319). It looks for where your Claude API code makes people wait and tries faster settings against your eval. [3]

Auth, config files & headless runs

  • Sign-in expiry is visible (v2.1.318). claude auth status shows loginExpiresAt, and claude -p JSON results include credential_expires_at. Text output from claude -p warns on stderr starting 10 days before a stored claude.ai sign-in ends. [2]
  • Console billing warnings (v2.1.319). Claude Code now warns when your claude.ai login ends and it continues on the sign-in from ant auth login, which bills your Claude Console organization. At startup it names that organization. [3]
  • CLAUDE_CODE_DISABLE_FEATURE_FLAGS (v2.1.319). It stops feature-flag fetching without turning off telemetry, and every flag uses its built-in default. [3]
  • ~/.claude.json handling (v2.1.318). Non-interactive launches no longer replace an invalid ~/.claude.json with defaults. They fail, explain how to restore it, and leave the file as is. Saves on shared network home directories are sturdier. Unattended runs stop rewriting the file when nothing changed. [2]
  • More honest exit codes. claude -p exits 1 when a full disk or quota loses its transcript or ~/.claude.json writes (v2.1.317) [1]. On self-hosted runners, setting CLAUDE_CODE_DISABLE_NESTED_SESSION_ID=1 makes claude -p run inside a session use that session's ID and transcript, as in earlier versions (v2.1.317). [1]
  • IDE extension install (v2.1.318). Claude Code no longer installs or updates the IDE extension when started in an IDE terminal. Use /ide from an outside terminal or your editor's extensions view. [2]

Tips & Techniques

  • Use denyInsteadOfPrompting for unattended work. In a background or CI-style session, a call that would need approval is denied and the turn keeps going, so the run doesn't sit waiting on a prompt nobody will answer. [3]
  • Check /status if you use auto mode behind a gateway or with telemetry off. After v2.1.319 it reports the server review accurately. Expect more prompts or denials where the server can't review. [3]
  • Watch sign-in expiry in automation. Read credential_expires_at from claude -p --output-format json, or loginExpiresAt from claude auth status, to renew before scheduled jobs start failing. [2]
  • Set effort per model, not just per session. Since v2.1.317, subagents on another model use that model's saved effort, so a cheaper search model can keep a lower effort than your main model. [1]
  • Keep .claude/settings.local.json out of commits. "Yes, and don't ask again" approvals land there as allow rules. Claude Code adds the file to your global git excludes only when it writes the file itself; if you created it by hand, add it to .gitignore. [7]

Recommended Default-Config Changes

  • Gateway or telemetry-off auto-mode users: decide on purpose. Either accept the stricter behavior, set CLAUDE_CODE_AUTO_MODE_SERVER=1 where your gateway passes the server check, or set CLAUDE_CODE_AUTO_MODE_SERVER=0 to keep the local classifier. [3][6]
  • Headless or background profiles: consider "permissions": {"denyInsteadOfPrompting": true} together with blockWritesOutsideWorkingDirectories from v1.12. [3]
  • If scripts depend on /loop keeping itself alive, set CLAUDE_CODE_LOOP_KEEPALIVE=1 in your settings env block. [3]
  • Privacy-restricted setups that only need feature flags off: use CLAUDE_CODE_DISABLE_FEATURE_FLAGS instead of turning off telemetry entirely. [3]
  • Self-hosted runner orchestrators: update log parsers that match retryable=true: or retryable=false:, since v2.1.318 adds reason=… after them. [2]
  • Still on fast mode for Opus 4.8? Move to Opus 5.5 before the November 30, 2026 removal, as covered in v1.12. [9]
