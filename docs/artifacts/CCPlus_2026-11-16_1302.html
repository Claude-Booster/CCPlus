[5] Claude Code v2.1.321 added Fable 5.2 (claude-fable-5-2) as the default Fable model, with a 1M context window. Saved Fable 5.1 picks move to it. [1] Four releases landed, v2.1.321, v2.1.322, v2.1.323 and v2.1.325. They move the CLI from v2.1.319 to v2.1.325; there are no v2.1.320 or v2.1.324 tags. What's New

Models

  • Claude Fable 5.2 (v2.1.321). claude-fable-5-2 is now the default Fable model, with 1M context, priced at $8/$40 per million input/output tokens and $0.20 per million for cache reads. [1] Anthropic's announcement reports 69.9% on FrontierSWE v2, against 62.3% for Opus 5.5 and 56.3% for Fable 5.1. It also says Fable 5.2 generates output up to 30% faster than Fable 5.1. [5]
  • Saved Fable 5.1 picks move to fable (v2.1.321). This happens right away on Pro and Max plans, and on Team and Enterprise once your organization allows it. Run /model claude-fable-5-1 to switch back. [1]
  • Cyber safeguards. Anthropic says Fable 5.2's classifiers block high-risk cyber activities, such as penetration testing, exploit generation and binary-based vulnerability work, and notes they will block most cybersecurity-related tasks. In early testing it saw about 60% fewer cyber blocks than with Fable 5.1. Blocked cyber queries get a response from Opus 4.8 instead. Mythos 5.2 is available only through the Cyber Verification and Life Sciences Verification programs, and in Claude Security for Enterprise customers. [5]
  • Fast mode. Fable 5.2 fast mode costs $16/$80 per million tokens, and Claude Code is one of the surfaces where it's offered. [5] Fast mode on Vertex now works in the global, us and eu regions, and falls back to standard speed if Vertex refuses it (v2.1.322). [2] Fast-mode labels in /fast, /config and /model now name your current model when it supports fast mode. When fast serving is rate-limited, Claude Code tries standard speed on the same model first (v2.1.321). [1]
  • No Enterprise default-model change. The release notes call Fable 5.2 the default Fable model. They don't announce a new overall default. [1]

Code Mode (experimental, v2.1.323)

  • What it is. Instead of asking for each Bash, Read or Edit call separately, Claude writes a short JavaScript program that makes the calls. One program can run calls in parallel, pass one result into the next call, and return only the part of the output Claude needs. You see the tool calls in the conversation. Press Ctrl+O to read the code. [3][6]
  • Turning it on. Set CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1 in your shell or in the env block of ~/.claude/settings.json. Project settings files can't turn it on. Claude Code asks you to confirm the first time. [6]
  • Requirements. An interactive terminal session on the native build. You need a Claude subscription or Console account on the Anthropic API, not a gateway, Bedrock, Vertex or Foundry. Supported models are Opus 5.5, Sonnet 5.5, Haiku 5.5 and Fable 5.2. It doesn't work with -p, the SDK, VS Code, the Desktop app, OpenTelemetry export, DISABLE_TELEMETRY, an API key helper or agent teams. [6]
  • Permission behavior. Your deny and ask rules and PreToolUse hooks still apply to each call the code makes. In auto mode, the classifier reviews the whole program before it runs, not each call, and it can't see values computed at run time. A PreToolUse hook on the REPL tool can read the code from tool_input.code. A Code Mode session can be resumed only with Code Mode on. [6]
  • Organization off switch. Set CLAUDE_CODE_EXPERIMENTAL_CODE_MODE to "0" in the managed settings env block. Managed settings can't turn it on for users. [6]

Permissions & sandbox

  • Sandboxed Bash prompts again by default (v2.1.325). Sandboxed commands now follow the normal permission flow. Set sandbox.autoAllowBashIfSandboxed: true to keep running them without prompts. If managed settings turn the sandbox on, set this key in your highest-ranking managed source. [4][7]
  • Skills in unattended runs (v2.1.325). Scheduled tasks and /loop now ask before running a skill that declares allowed-tools or hooks. To keep such a skill unattended, add Skill(name) to permissions.allow. Read-only git commands in a repository that isn't the project's or one you trusted now ask first. Use --add-dir, not additionalDirectories, to let them run without prompts. [4]
  • Safer startup (v2.1.323). If you start with --permission-mode auto or defaultMode: auto and auto mode isn't available, Claude Code now starts in Manual mode. Before, it could start in a mode that allowed more. A --settings file that isn't valid JSON and has a sandbox key now stops startup. When sandbox settings fail validation, claude -p and the SDK stop instead of running Bash unsandboxed. [3]
  • "Don't ask again" is more careful (v2.1.323). An allow rule that looks like it contains a secret, or that would be saved to a git-tracked settings.local.json, now lasts only for the session. Bash allow rules with a * in a variable's value, such as Bash(PORT=* npm run dev), get a startup warning. /security-review now asks before it runs. [3]
  • Sandbox and worktrees (v2.1.323, v2.1.325). Inside the sandbox, git worktree add/move/remove now fail as read-only. So do commits in a worktree the session wasn't started in or given. Write access granted through a symlink is ignored; grant the real path instead. [3] The sandbox also refuses writes to .claude settings, skills, agents, commands and hooks in added directories (v2.1.325). [4]
  • Security fixes. v2.1.321 stops MCP OAuth from sending refresh tokens to another host on a redirect. It also applies deny rules to files that cp/mv write into a directory. [1] v2.1.323 fixes many Bash, sandbox and allow-rule bypasses, including wildcard rules like Bash(ls*) and sudo/env wrappers. [3] v2.1.325 fixes zstd response decoding and more compound-command gaps. Relative rules such as Read(./.env) now keep covering the project after a cd. [4]

Context, models & agents

  • Unrecognized model IDs assume 1M context (v2.1.323). This was 200K before. Sessions on other vendors' models with smaller windows can fail every turn once full. Set CLAUDE_CODE_DISABLE_1M_CONTEXT=1 before they fill. [3] CLAUDE_CODE_MAX_CONTEXT_TOKENS now also sets the window for unrecognized claude- IDs, such as a gateway alias (v2.1.325). Sessions on many gateways and Foundry now compact instead of failing with a context-length error. [4]
  • Subagents (v2.1.325). A subagent cut off at the output token limit is now asked to give its full answer again, more briefly. Subagents with their own model are no longer moved to the plan-mode model under opusplan or haiku. [4] CLAUDE_CODE_DISABLE_AGENT_PROGRESS_SUMMARIES=1 turns off subagent progress summaries and the requests that write them (documented in v2.1.323; available since v2.1.318). [3]
  • Leaner background output (v2.1.321). Background command notifications and TaskStop results over 1,000 characters show Claude only the start and end. [1]
  • Removed subagentStatusLine (v2.1.323). Subagent rows always use the default look. Settings files that still contain the key load as before. [3]

Plugins, MCP & mods

  • Version ranges for plugins (v2.1.323). engines["claude-code"] in plugin.json keeps a plugin from installing, updating or loading outside its stated version range. claude plugin validate type-checks TypeScript hooks modules; --strict fails on findings. A plugin's agent setting is deprecated. [3]
  • MCP client (v2.1.323). The v1 MCP client is removed. MCP_SDK_GENERATION=v1 now runs the v2 client in a compatibility mode. The tool that finishes an MCP sign-in now asks you to confirm, even in bypass and auto modes. .mcp.json approvals must match the server's exact name. [3]
  • Managed plugin changes (v2.1.325). pluginDigests is deprecated and ignored. Plugins from a managed remote marketplace that are listed in prependPlugins/appendPlugins count as the organization's. .claude/skills in --plugin-dir plugins no longer load from a session started above them. [4]
  • Remote Control (v2.1.321, v2.1.325). claude remote-control --settings <file> applies a settings file to every session it starts [1]. It now exits with status 4 when it stops by itself and 69 when it can't register, so a service manager can restart it. [4]

Networking, IDE & other

  • Proxies (v2.1.323). Organization settings and policy requests no longer use a proxy set only by ALL_PROXY; set HTTPS_PROXY instead. The maximum for CLAUDE_CODE_OVERLOADED_RETRY_MAX_DELAY_MS rose from 64000 to 300000. [3]
  • Credentials kept out of subprocesses (v2.1.323, v2.1.325). Claude Code's own ripgrep, most internal git commands and the sandbox's helper programs now run without most of its sign-in tokens and API keys. [3][4]
  • VS Code. A trust prompt before the first session in an untrusted folder, and live Bash output under the command's card (v2.1.323) [3]. Prompt suggestions, which Tab accepts; turn them off with promptSuggestionEnabled: false (v2.1.325). [4]
  • Usage credits (v2.1.323). When a model needs usage credits that are off or used up, an options menu offers to stop, switch to usage credits or upgrade. [3]

Tips & Techniques

  • Try Code Mode on wide, repetitive work. The docs suggest it for the same change across many files, searches whose results need filtering, and independent commands that can run in parallel. Keep deny rules or hooks for calls you must control, because the auto-mode classifier sees the program, not run-time values. [6]
  • Watch for new sandbox prompts after updating. If prompts appear for commands that ran silently last week, that's the v2.1.325 sandbox default. Decide whether you want the prompts. If you don't, set autoAllowBashIfSandboxed explicitly. [4]
  • Pin Fable 5.1 only if you have a reason. After v2.1.321, saved Fable picks follow fable to 5.2. Use /model claude-fable-5-1 if a workflow depends on the old model. [1]
  • On gateways with non-Claude or aliased models, set the context window explicitly with CLAUDE_CODE_MAX_CONTEXT_TOKENS or CLAUDE_CODE_DISABLE_1M_CONTEXT=1. That way the new 1M assumption doesn't skip compaction. [3][4]

Recommended Default-Config Changes

  • Sandbox users who relied on auto-allow: add "sandbox": {"autoAllowBashIfSandboxed": true}. Organizations that turn the sandbox on through managed settings should set it in their highest-ranking managed source. [4]
  • Scheduled tasks and /loop that call skills: add "Skill(<name>)" to permissions.allow for each skill that declares allowed-tools or hooks. [4]
  • Organizations: choose a Code Mode policy. Leave it opt-in, or block it with "env": {"CLAUDE_CODE_EXPERIMENTAL_CODE_MODE": "0"} in managed settings. [6] Team and Enterprise admins should also decide whether to allow Fable 5.2, since saved Fable 5.1 picks move only once the organization allows it. [1]
  • Networks with only ALL_PROXY set: also set HTTPS_PROXY. [3]
  • Plugin authors: declare engines["claude-code"] and run claude plugin validate --strict in CI. [3]
  • Clean-up: you can remove subagentStatusLine from settings [3]. Managed configs can drop pluginDigests. [4]
  • Still on fast mode for Opus 4.8? Move to Opus 5.5 before the November 30, 2026 removal, as covered in v1.12. [10]
