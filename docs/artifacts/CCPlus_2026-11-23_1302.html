Summary

There was no new model this week. Five releases, v2.1.326 through v2.1.330, move the CLI from v2.1.325 to v2.1.330. [6][7] v2.1.326 is a large permissions and sandbox release. Sandboxed commands no longer write to some sensitive home folders by default. File tools refuse writes to Claude Code's sign-in files. Sessions with no mode set start in auto mode, not Manual, while the organization's policy hasn't loaded. [1] /code-review now reports only bugs and CLAUDE.md violations, and /simplify handles cleanups (v2.1.328). With no target, it reviews the whole branch against the default branch (v2.1.329). [3][4] v2.1.330 adds sign-in to organizations managed in the Enterprise Admin Console and easel, a built-in chart mod. It also lets recurring scheduled tasks and /loop run up to 30 days. [5] Separately, the Claude Code team published guidance on how it verifies changes. [8]

What's New

Models & auto mode

  • No new model or default-model change. Anthropic's news page has no model or Claude Code posts after the November 9 Fable 5.2 announcement covered in v1.14. [10]
  • Auto mode for Opus 4.6 and Sonnet 4.6 on third-party providers (v2.1.328). This covers Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry and the Claude apps gateway. Interactive sessions with no permission mode start in auto mode. Plan mode and Bash prompts on these models now use and offer auto mode. disableAutoMode turns both off. [3]
  • Auto mode as the fallback start mode (v2.1.326). Terminal and VS Code sessions with no mode set now start in auto mode, not Manual, while the organization's policy hasn't loaded. Once settings load, they take a server-managed defaultMode. They fall back to Manual if settings fail with no stored copy and the policy fails or requires it. Organizations with the Claude Code + Cowork HIPAA configuration also start in auto mode by default. [1]
  • Auto mode is stricter about allow rules (v2.1.326, v2.1.327). It ignores more wildcard shell allow rules, such as ones that name no program or start with $HOME. It also ignores rules that run any package, like Bash(pnpm dlx *). The safety check decides those commands instead. [1][2] Auto mode's notice about falling back to billed classifier requests now says an upcoming release removes that fallback (v2.1.327). [2]
  • Unrecognized model names (v2.1.330). Names containing "sonnet" or "haiku" now get the shorter system prompt, like other unrecognized names. CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0 gives every model the full prompt. [5]
  • Model choice in skills and subagents (v2.1.327, v2.1.330). Subagents started without a model stay on the model they started on when resumed, even after /model (v2.1.327). [2] Skills with a model setting no longer move subagents, forks, compaction or /recap off the session's model, unless they are context: fork skills (v2.1.330). [5] In plan mode, automatic compaction now uses the model answering you, such as Opus with opusplan, so it can cost more (v2.1.326). [1]
  • Output-token limit retry. v2.1.326 retries a request with the API's reported maximum when max_tokens exceeds a model's limit. [1] v2.1.329 removed that retry, and v2.1.330 reverted the removal, so the retry is back. [4][5]

Permissions, sandbox & security (mostly v2.1.326)

  • Sandbox writes to the home folder. Sandboxed commands on macOS, Linux and WSL no longer write to some sensitive home folders by default. You can allow some of them with sandbox.filesystem.allowWrite in user or managed settings. After a command, the sandbox sets aside unexpected entries in a repository's .git folder. [1]
  • Sign-in files are protected. Claude's file tools refuse writes to Claude Code's sign-in files, such as .credentials.json. The Bash check asks before more commands that reach them. [1]
  • Hooks. A hook's "decision": "block" now holds in more cases, so a hook that always prints one may start blocking calls. [1] mcp_tool hooks accept "onFailure": "block", like command and HTTP hooks (v2.1.328). [3] Prompt hooks accept model aliases such as haiku or sonnet in their model field (v2.1.330). [5] Managed PostToolUse hooks no longer fire for calls refused before they ran (v2.1.328). [3] The folder trust dialog now warns where a folder's hooks are declared (v2.1.329). [4]
  • Trust for added folders. --add-dir and /add-dir in local terminal sessions show the trust prompt for a folder you haven't trusted. claude --bg refuses such a folder. [1]
  • More commands ask first. Some cp and mv commands, some PowerShell commands, and some tool calls in bypass permissions mode now ask, or are refused where no one can answer (v2.1.326). [1] More rm commands aimed at the root, home, a top-level folder or the working folder now ask (v2.1.330). [5] permissions.blockReadsOutsideWorkingDirectories covers more Bash commands (v2.1.327). [2]
  • Worktrees. ExitWorktree asks before removing a worktree that may hold unsaved work (v2.1.327). [2] It refuses while a background subagent or command may still be running there (v2.1.326). [1] v2.1.330 fixes it deleting a worktree that another running session was using. [5]
  • Managed settings. A managed autoMode.environment list without "$defaults" now replaces every built-in entry in Claude Desktop and Agent SDK apps too. Enabled plugins that were refused for a malformed plugin.json display field now load, with their hooks and MCP servers, so admins should check what they deploy. [1] deniedMcpServers name entries now hide only the named claude.ai connector; deny its exact URL to block every connector at that URL (v2.1.330). [5]

Code review

  • Narrower /code-review (v2.1.328). On most models it reports only bugs and CLAUDE.md violations. Run /simplify for reuse, simplification and efficiency cleanups. Each finding is marked Important, Pre-existing or Nit, and each summary ends with a suggested fix. [3]
  • Whole-branch review (v2.1.329). /code-review with no target now reviews the whole branch against the default branch on most models. A fix stops it losing the diff on multi-commit branches. Given a PR number with --fix, or a PR URL, it stops without reviewing when gh pr diff is refused or fails. [4]

Scheduled tasks, /loop & background work

  • 30-day recurring tasks (v2.1.330). Recurring scheduled tasks and /loop run up to 30 days instead of 7 while their session keeps running, and say when they end. Tasks made before this release still end at 7 days. [5]
  • Reschedule saved tasks (v2.1.329). In new signed-in sessions, most scheduled tasks saved by earlier versions need scheduling again. --resume of their own session still runs them. "Exit and stop tasks" now ends the session's scheduled tasks so they don't run again on resume. /tasks now lists scheduled tasks, /loop wakeups, the goal and forks. [4]
  • Headless runs (v2.1.328). CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME stops claude -p --resume/--continue from running a tool call that a hook deferred. With CLAUDE_CODE_FORK_SUBAGENT=0, claude -p counts a background subagent and the ones it waits for against one 10-minute wait. Raise CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS for longer chains. [3]

Code Mode (experimental)

  • Fewer restrictions. Code Mode can now be on with agent teams (v2.1.326) [1], and with OpenTelemetry events and metrics, but not tracing (v2.1.329). It also starts when telemetry, nonessential traffic or feature flags are off. Administrators can still keep it off in managed settings. [4]
  • Hook behavior. A PreToolUse hook that errors no longer refuses a script's tool call. Set "onFailure": "block" on hooks that must refuse (v2.1.329). [4] Code Mode no longer runs UserPromptSubmit hooks, managed ones included, on script output. To redact that output, use a PostToolUse hook with updatedToolOutput (v2.1.328). [3]

Sign-in, MCP, mods & other

  • Enterprise Admin Console organizations (v2.1.330). After claude auth login, Claude Code applies the organization's settings and uses its cloud provider or gateway. CLAUDE_CODE_FULL_SIGN_IN_LINK=1 prints the full sign-in link. [5]
  • easel (v2.1.330). A built-in mod that draws charts when asked and under MCP metrics results. It's on Pro and Max, and where available on Team and Enterprise, on macOS and Linux. Turn automatic charts off in /config. [5]
  • MCP from stdin (v2.1.327). claude mcp add-json <name> - reads the server's JSON from stdin, so tokens stay off the command line. It isn't available inside a Claude Code session. claude mcp add --scope project now stops instead of overwriting a .mcp.json that has no mcpServers key. [2]
  • Diagnostics. /status lists broken agent, skill, command and output style files, ignored permission settings and hook matchers that never match. /config notes when other settings override a row (v2.1.327). [2] /status and claude doctor flag an OpenTelemetry exporter with no endpoint (v2.1.328). [3] A startup warning flags --allowedTools, --disallowedTools or --tools entries that don't look like complete rules (v2.1.326). [1]
  • Faster first Bash command (v2.1.327). Shell start-up files may now run before the command is approved, even if it's refused. CLAUDE_CODE_DISABLE_SHELL_HEAD_START=1 turns this off. [2]
  • Other settings. attributionProject names a session's billing group on Claude apps gateways, and /tui classic names the non-fullscreen renderer (v2.1.327). [2] OTEL_RESOURCE_INCLUDE_HOST adds host name and ID to OpenTelemetry resources; it's off by default (v2.1.326). The /claude-api skill now builds agents on Managed Agents by default (v2.1.326). [1]
  • VS Code (v2.1.330). /fork, /workflows, and the settings claudeCode.escapeStopsClaude, claudeCode.pinPrompt and claudeCode.contextUsageThreshold. [5]
  • Notable fixes (v2.1.330). Freezes of up to several minutes after compacting a very long conversation, and WebFetch freezing on some pages. [5]

Tips & Techniques

  • Give Claude a verify skill. The Claude Code team recommends a skill in .claude/skills/, close to the code, that boots, drives and inspects the app. Stress-test it until it's reliable. [8]
  • Check behavior end to end, not just the diff. Have Claude run the real app: Claude in Chrome for web, computer use for desktop, a mobile MCP, or a local service for backends. Run tests, build and lint before opening a PR. [8]
  • Enforce checks with hooks, CLAUDE.md and REVIEW.md. Use a hook that runs tests when Claude finishes, or a goal of a passing suite. Turn repeated mistakes into CLAUDE.md rules or hooks. Put review focus in REVIEW.md; Code Review reads it from the base branch, so a PR can't weaken its own gate. [8]
  • Don't let Claude paper over flaky tests. Find the root cause instead of skipping, sleeping or retrying, or delete the test and document why. [8]
  • Pair /code-review with /simplify. Since v2.1.328, /code-review looks only for bugs and CLAUDE.md violations. Run /simplify separately if you want cleanup suggestions. [3]
  • Re-create long-running loops after updating. Tasks saved by earlier versions may need scheduling again (v2.1.329), and only tasks made on v2.1.330 or later get the 30-day limit. [4][5]

Recommended Default-Config Changes

  • Sandbox users: if sandboxed tools now fail to write to a folder under your home directory, add only that path to sandbox.filesystem.allowWrite in user or managed settings. [1]
  • Hook authors: audit hooks that always print "decision": "block", since they may now block. Add "onFailure": "block" to hooks that must refuse when they fail, including mcp_tool hooks and hooks that guard Code Mode. [1][3][4]
  • Auto mode users: don't rely on broad allow rules like Bash(pnpm dlx *) or $HOME-prefixed wildcards. Auto mode now ignores them, so the safety check decides. [1][2]
  • Organizations: if you don't want auto mode on Opus 4.6/Sonnet 4.6 via third-party providers, or as the start mode before policy loads, set disableAutoMode. [1][3] Add "$defaults" to any managed autoMode.environment list. Re-check deployed plugins with malformed display fields. [1] Review deniedMcpServers name entries and deny exact URLs where you meant to block every connector at that URL. [5]
  • MCP setup scripts: use claude mcp add-json <name> - so tokens aren't passed on the command line. [2]
  • Gateway users with non-Claude models named "sonnet" or "haiku": set CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0 if you need the full system prompt. [5]
  • Still on fast mode for Opus 4.8? Move to Opus 5.5 before the November 30, 2026 removal, as covered in v1.12. [11]
