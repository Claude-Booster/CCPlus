Summary

No new model shipped this period, but two default behaviors changed in ways worth acting on. First, Claude Code now reads AGENTS.md directly: a repository with no CLAUDE.md loads its AGENTS.md as project instructions automatically, configurable under Project instructions in /config (v2.1.277). [7][10] Second, auto mode's safety classifier now runs server-side by default for Claude API and Enterprise users and on Bedrock, Vertex, Foundry and gateways, and those server-side checks are no longer billed as classifier-overhead tokens (v2.1.278). [8][9] Around those, releases v2.1.271–v2.1.278 landed since the prior period's v2.1.270 (v2.1.272 and v2.1.276 are bugfix/regression-only). [11] Other notables: the deprecated TaskOutput tool was removed, a send-now key batches queued messages, skills and plugins enabled on your claude.ai account now sync to terminal sessions, per-command allowed_domains arrived for sandboxed auto mode, and subagents can skip project CLAUDE.md files with omitClaudeMd. CLI advanced v2.1.270 → v2.1.278.

What's New

Project instructions & AGENTS.md

  • AGENTS.md read directly (v2.1.277). A repository already set up for other coding agents works with no CLAUDE.md, import, or setting: when your working directory (and the directories above it) have no CLAUDE.md or CLAUDE.local.md, Claude Code loads every AGENTS.md / .claude/AGENTS.md it finds. The default Project instructions value is claude-md-or-agents-md; switch to claude-md-and-agents-md to read both, claude-md to ignore AGENTS.md, or managed-only. Reading AGENTS.md directly requires v2.1.277+ and is not yet available on Bedrock, Vertex, Foundry, or telemetry-disabled sessions (import it from a CLAUDE.md there). [7][10]
  • omitClaudeMd for subagents (v2.1.271). A new agent-frontmatter and --agents JSON field lets custom and plugin subagents run without your user, project, and local CLAUDE.md files; managed policy files still load. [1]

Auto mode & the safety classifier

  • Server-side classifier is now the default — and free of classifier-overhead charges (v2.1.278). For Claude API and Enterprise accounts, and on Bedrock, Vertex, Foundry and gateways, auto mode now asks the server to run its safety checks as part of the session's own model requests and does not charge for them. When the server's checks can't reach a session (typically a gateway/proxy that strips or rewrites the safeguards request field or safeguard_results responses), Claude Code falls back to its own billed classifier requests and shows a one-time notice. A new Auto mode server row in /status reads Enabled or Disabled accordingly. Pro, Max and Team plans never see the notice. [8][9]
  • CLAUDE_CODE_AUTO_MODE_SERVER=0 opt-out. Set it before starting a session to keep using Claude Code's own classifier on a gateway that can't pass the checks through; the variable is not read on a direct connection to the Anthropic API and is documented as temporary. [8][9]
  • Per-command allowed_domains in sandboxed auto mode (v2.1.271). Bash, PowerShell and Monitor calls can declare the hosts they need; those hosts are reviewed alongside the command and opened for that command alone, and other hosts are refused. [1]
  • Inline ! commands and subagent hand-backs (v2.1.271). A skill's or slash command's inline ! shell commands now follow default-mode permission rules instead of the classifier (a command no rule decides runs as a reviewed tool call), and a subagent reports back to its caller through a dedicated hand-back call the classifier reviews, rather than its last message being reviewed after the fact. [1]

Tools & session controls

  • TaskOutput tool removed (v2.1.277). Claude now reads a background task's output file with Read; the taskOutputMaxChars setting and TASK_MAX_OUTPUT_LENGTH no longer have any effect. [7]
  • Send-now key (v2.1.275). Ctrl+Enter (or Ctrl+X Ctrl+S) interrupts the current turn and sends all queued messages at once; sent and queued messages show in gray until the model receives them. [5]
  • Monitor watches always have a deadline (v2.1.271). At most 30 minutes (10 in a single-prompt -p run), after which Claude is notified to re-arm — replacing the no-timeout persistent option. [1]
  • Subagent results are framed as subagent output (v2.1.277). A subagent's result now reaches the main agent under a header marking it as subagent output, indented, so text in a result cannot pass as the session's own instructions; workflow-script agent() prompts on Bedrock/Vertex/Foundry are likewise framed as script-authored text for the classifier. [7]

Skills, plugins & marketplaces

  • claude.ai skills/plugins sync to the terminal (v2.1.275). The skills and plugins you enable on your claude.ai account now sync to terminal sessions signed in with it; opt out with syncClaudeAiSkills: false or syncClaudeAiPlugins: false. [5]
  • /plugin install <plugin> --marketplace <source> (v2.1.275). Offers to add the marketplace before installing the plugin. [5]
  • --accept-command <sha256> (v2.1.271). On claude plugin install and claude plugin update, accepts exactly the command a previous --json run displayed instead of a blanket -y. [1]
  • npm plugins install without running scripts (v2.1.275). Plugins from an npm source are now fetched with npm pack --ignore-scripts and integrity-verified, so a package's install scripts no longer run. [5]

Config, telemetry & provider parity

  • New environment variables. CLAUDE_CODE_MCP_STARTUP_WAIT_MS bounds how long the first non-interactive turn waits for connecting MCP servers (0 = don't wait, v2.1.274) [4]; CLAUDE_CODE_GATEWAY_HINT_HEADERS=1 opts in to new x-claude-code-* request-class/agent-type/compaction hint headers for LLM gateways (v2.1.273) [3]; and CLAUDE_GATEWAY_PROXY_IS_EGRESS_BOUNDARY=1 makes a Claude apps gateway hand its forward proxy the hostname instead of resolving it locally (v2.1.277). [7]
  • OpenTelemetry additions (v2.1.273–274). OTEL_LOG_TOOL_DETAILS=1 now includes real agent, skill, plugin and MCP server names on cost/token metrics [3]; the claude_code.llm_request trace span gains an effort attribute; and a new claude_code.managed_settings_resolved event (with redacted settings under OTEL_LOG_MANAGED_SETTINGS=1) reports managed-settings sources and policy-helper state. [4]
  • Chargeback markup in modelPricing (v2.1.271). The modelPricing managed setting and the Claude apps gateway pricing block now accept a multiplier above 1, up to 10, for marked-up internal chargeback rates. [1]
  • Cloud-provider MCP defaults (v2.1.274). Bedrock, Vertex, Foundry and telemetry-disabled installs now use the v2 MCP client and MCP 2026-07-28 negotiation with direct HTTP servers by default, matching other installs; opt out with MCP_SDK_GENERATION=v1 or MCP_PROTOCOL_NEGOTIATION=legacy. [4]
  • /code-review uses leaner inline prompts (v2.1.274). For every model that has no tuned settings of its own, /code-review now uses lean inline review prompts instead of spawning many review subagents. [4]
  • "type": "sdk" MCP entries are skipped (v2.1.274). SDK-type MCP entries in .mcp.json, settings, plugins and agent files are now skipped with a warning — only an SDK host application can register in-process servers. [4]

UI, IDE & smaller changes

  • Fable always shows in /model on the Anthropic API (v2.1.277). It is greyed out only when your organization's settings disable it. [7]
  • Mouse support in the fullscreen /config panel (v2.1.271). The wheel scrolls the list and a click on a value changes it. [1]
  • Fork a Remote Control session from the Claude app (v2.1.273). The fork runs as a background session on your computer. [3]
  • Markdown artifacts render as styled pages; watch up to 10 (v2.1.271). Markdown files published as artifacts now render with document typography and syntax highlighting, and a session can watch up to 10 published artifacts for republishes (up from 5). [1]
  • Smaller dynamic workflows on Pro (v2.1.271). The default dynamic-workflow size is now small on Pro plans, and the medium-size guideline dropped from 15 to 10 agents. [1]

Security hardening

  • Prompt-injection framing (v2.1.277). Alongside the subagent-result framing above, invisible Unicode formatting and tag characters in a prompt are now removed, and the cleaned prompt is shown for review before it is sent. [7]
  • Secret redaction in plugin/marketplace URLs (v2.1.275). Plugin and marketplace messages, logs, claude plugin marketplace list, and the VS Code plugin dialog no longer show a password or token stored in a git, ssh or marketplace URL. [5]
  • Tighter Bash permission checks (v2.1.271, v2.1.274). The checker no longer misses the file that fmt/column-style commands read after an unrecognized option, no longer skips files a wildcard expands to, and cannot be fooled by shell variable-declaration flags [1]; commands that loop over or assign certain special shell variables now ask for permission, and worktree-isolated sessions refuse Bash commands with certain nested shell expansions. [4]
  • ${VAR} redaction in MCP errors (v2.1.274). MCP connection errors and the MCP login tool's description no longer show secrets resolved from ${VAR} placeholders in MCP configs. [4]

Tips & Techniques

  • Adopt AGENTS.md for cross-tool repos. If your repo is already set up for other agents, delete any @AGENTS.md-import CLAUDE.md or SessionStart-hook workaround and let Claude read AGENTS.md directly; set Project instructions to claude-md-and-agents-md when you want both files. [7][10]
  • Give subagents a clean context. Set omitClaudeMd on a custom or plugin subagent whose task shouldn't inherit your project's CLAUDE.md; managed policy still applies. [1]
  • Batch queued messages. Type several follow-ups while Claude works, then press Ctrl+Enter to interrupt and send them all at once. [5]
  • Scope network access per command. In sandboxed auto mode, rely on the new per-command allowed_domains review so a command's hosts open only for it rather than widening access for the whole session. [1]
  • Pin the exact plugin command in CI. Run claude plugin install --json, capture the displayed command's SHA-256, and re-run with --accept-command <sha256> instead of a blanket -y. [1]
  • Read background output with Read. With TaskOutput gone, point at the task's output file directly; drop any reliance on taskOutputMaxChars / TASK_MAX_OUTPUT_LENGTH, which are now no-ops. [7]

Recommended Default-Config Changes

  • Retire your AGENTS.md workarounds. If you previously symlinked or imported AGENTS.md from a CLAUDE.md, or printed it from a SessionStart hook, remove the workaround so Claude reads it once directly (v2.1.277+); note that a CLAUDE.local.md on the path suppresses AGENTS.md unless you set claude-md-and-agents-md. [7][10]
  • Decide your auto-mode classifier posture. Leave the default on so server-side checks run un-billed; set CLAUDE_CODE_AUTO_MODE_SERVER=0 only when you know your gateway can't forward the safeguards field and safeguard_results unchanged. Fixing the gateway to pass traffic through is the better long-term choice. [8][9]
  • Control claude.ai sync. If you don't want your account's skills/plugins pulled into terminal sessions, set syncClaudeAiSkills: false and/or syncClaudeAiPlugins: false. [5]
  • Check anything that ran npm plugin install scripts. npm-sourced plugins now install with --ignore-scripts; if a plugin relied on a postinstall step, adjust it. [5]
  • Drop taskOutputMaxChars. Remove it from settings — it and TASK_MAX_OUTPUT_LENGTH no longer do anything now that TaskOutput is gone. [7]
