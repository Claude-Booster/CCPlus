Summary

This period brought the biggest default changes in months. A new model generation arrived: Claude Opus 5.5 is now the default Opus model (v2.1.280), Sonnet 5.5 is the default Sonnet on the Anthropic API (v2.1.284), and Haiku 5.5 is the default Haiku there (v2.1.293). All three have 1M-token context windows. [1][5][14][18] Pro and Team Standard plans now default to Opus too, so the default model is Opus 5.5 on every Anthropic plan. [1][19] Second, auto mode is now the starting permission mode for interactive terminal and VS Code sessions on every plan and provider when you haven't configured a mode (v2.1.283–284). [4][5][20] Third, Claude Mods shipped (v2.1.287). Mods are plugins that run JavaScript/TypeScript handlers inside Claude Code, so they can draw panes, add commands, and step into tool calls. [8][21] Other notable additions: "attribution": false, maxProseWidth, onFailure: "block" for hooks, an effort parameter on the Agent tool, Ultracode as its own toggle, and new managed model and provider controls (deniedModels, availableModelsMatch, allowedProviders). Releases v2.1.280–v2.1.296 landed (no v2.1.279 tag), so the CLI moved from v2.1.278 to v2.1.296. [22]

What's New

Models & defaults

  • Claude Opus 5.5 (claude-opus-5-5) is the default Opus (v2.1.280). It has a 1M context window and costs $4/$20 per Mtok, with cache reads at $0.20/Mtok. The models overview recommends starting with it for most workloads, and lists its default API effort as medium. [1][18]
  • Claude Sonnet 5.5 (claude-sonnet-5-5) is the default Sonnet on the Anthropic API (v2.1.284). 1M context, $2/$10 per Mtok, $0.10/Mtok cache reads (v2.1.284 first listed $0.20; v2.1.296 corrected the pricing). [5][17][18]
  • Claude Haiku 5.5 (claude-haiku-5-5) is the default Haiku on the Anthropic API (v2.1.293). 1M context, $0.10/$0.50 per Mtok, rising to $0.50/$2.50 for prompts over 100K tokens. [14][18]
  • Opus is now the default on Pro and Team Standard (v2.1.280). Those plans used to default to Sonnet. They now match Max, Team Premium and Enterprise. The model docs list default → Opus 5.5 for Pro, Max, Team, Enterprise and the Anthropic API. On the Anthropic API, the opus/sonnet/haiku aliases resolve to the 5.5 models; other providers resolve some aliases to earlier versions. [1][19]
  • Effort carry-over changes (v2.1.280). An effort level saved before /effort became per-model no longer applies to newly released models such as Opus 5.5; they start at their own default. Opus 4.7, Opus 4.8 and Fable 5 no longer hold their launch-default effort over an explicitly configured level. [1]
  • 1M context by default beyond the Anthropic API. Sessions behind a custom ANTHROPIC_BASE_URL now use the 1M window of models that have one (v2.1.285). Opus 4.7+ and Fable default to 1M on Bedrock, Vertex, Foundry and the Claude apps gateway without a [1m] suffix (v2.1.287). CLAUDE_CODE_DISABLE_1M_CONTEXT=1 keeps 200K, and /autocompact 200k helps if a gateway stops at 200K. [6][8]
  • Ultracode is its own toggle (v2.1.284). Toggle it with Tab in /effort or /effort ultracode [on|off]. It no longer forces xhigh effort and stays on at any effort level. [5][19]

Permissions & auto mode

  • Auto mode is the starting mode (v2.1.283–284). In v2.1.283, interactive sessions on third-party providers or with telemetry off began starting in auto mode when no permission mode is configured. v2.1.284 extended this to interactive terminal and VS Code sessions on every plan and provider. permissions.defaultMode still overrides it. v2.1.285 did the same for claude -p and Python Agent SDK sessions on third-party providers or with telemetry off, where --permission-mode still wins. [4][5][6][20]
  • Server-side classifier is stricter and wider (v2.1.281–282). Where the classifier runs server-side, read-only and sandboxed shell commands now also wait for its review. CLAUDE_CODE_AUTO_MODE_SERVER now applies on direct Anthropic API connections too (0 opts out, 1 opts in), which reverses the v1.8 note that the API ignored it. The server-side classifier is also the default on the direct API when telemetry is off. [2][3]
  • Safer unattended rm (v2.1.281). A recursive rm whose target comes only from command substitution (e.g. rm -rf "$(pwd)") now asks, even under --dangerously-skip-permissions. In skip-permissions and auto mode, the dangerous-rm prompt now waits 2 minutes and then denies the command with a rewrite hint. CLAUDE_CODE_DISABLE_DANGEROUS_RM_TIMEOUT=1 turns the timeout off. [2]
  • "Yes, but ask again next time" (v2.1.284). Auto mode's prompt before a read outside the working directories can now allow one read without allowing later ones. [5]

Mods, hooks & plugins

  • Claude Mods (v2.1.287). Plugins can now change deeper behavior through in-process JS/TS event handlers. They can draw panes and bands, rewrite tool calls and prompts, and add instant /commands. Mods are on by default from v2.1.287, are not sandboxed, and run with your permissions, so install them only from trusted marketplaces. disableAllHooks or --safe-mode turns installed mods off. Before installing, claude plugin validate lists what a mod hooks and calls. Later releases extended the mods API (agent.spawn, prompt.autocomplete, $.ui.notify, cached $.model.complete). [8][10][13][16][21]
  • "You should know" built-in mod (v2.1.287). A side agent watches longer tasks and flags things you or Claude might miss. It is off by default; enable it with /plugin enable cc-plugin-you-should-know@builtin (first-party sessions with telemetry on). [8][21]
  • onFailure: "block" for command and HTTP hooks (v2.1.295). With this set, a hook that can't start, times out, or exits with an unexpected code blocks the action. Without it, the action goes through. [16]
  • Plugin CLI additions. claude plugin configure and plugin install --config <server>.<key>=<value> (v2.1.285) [6]; claude plugin install --marketplace <source> (v2.1.292) [13]; and MCP-server checks in claude plugin validate (v2.1.281). [2]

Agents, tools & sessions

  • Per-subagent effort and compaction. The Agent tool gained an effort parameter (v2.1.292). Subagent frontmatter and --agents gained autoCompactWindow, and CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL pins every workflow agent to one model (v2.1.296). [13][17]
  • Background command time limit (v2.1.285, narrowed v2.1.288). Background Bash/PowerShell commands stop at their timeout (default 30 min, max 2 h), but only in unattended sessions (-p, Agent SDK, CI, cloud). Interactive sessions have no limit. [6][9]
  • WebSearch budget refills (v2.1.290). Interactive sessions now get 100 calls/hour on a rolling basis, replacing the old hard stop at 200 calls (CLAUDE_CODE_WEB_SEARCH_REFILLS_PER_HOUR sets the rate). CLAUDE_CODE_DISABLE_WEB_FETCH turns WebFetch off (v2.1.285). [11][6]
  • Bigger MCP description limits. Up-front MCP tool descriptions and server instructions now allow 4,096 characters, up from 2,048 (v2.1.296). Descriptions loaded through tool search allow 16,384 (v2.1.295). CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH overrides the cap (v2.1.280). [17][16][1]
  • Send-now backgrounds instead of cancelling (v2.1.281). Ctrl+Enter now moves running tools to the background instead of cancelling the turn. [2]
  • --bare is barer (v2.1.286). It connects only the MCP servers named on the command line, sends no system reminders, and starts no background tasks. [7]
  • Misc. /doctor prompt-audit audits CLAUDE.md, skills, agents and commands for prompting patterns written for older models (v2.1.283) [4]; /mcp reconnect all (v2.1.284) [5]; claude --desktop (v2.1.285) [6]; /code-review --max-findings and Up-arrow recovery of a prompt cleared with Ctrl+C (v2.1.288) [9]; the Read tool's allow_large option (v2.1.296). [17]

Settings & enterprise controls

  • "attribution": false (v2.1.281). Hides all commit and PR attribution. Older CLIs skip a settings file that contains it, so keep the object form in files shared across versions. [2]
  • maxProseWidth (v2.1.282). Caps how wide Claude's prose runs in wide terminals, while tables and code blocks keep the full width. [3]
  • Model and provider allow/deny (v2.1.283, v2.1.285). These are managed settings only. deniedModels blocks named models even when availableModels allows them. availableModelsMatch: "exact" keeps new releases blocked until they are listed. allowedProviders limits which API providers a machine may use. [4][6][19]
  • Project settings can do less (v2.1.282–290). Project and local settings now ignore OpenTelemetry export, endpoint and content-capture variables (v2.1.282). They can no longer widen or turn off an admin-required sandbox (v2.1.285). They can no longer turn on Claude in Chrome or set CLAUDE_CODE_DISABLE_ATTACHMENTS (v2.1.290). [3][6][11]
  • Reserved skill namespaces (v2.1.282). Local skills, commands and MCP servers named anthropic-skills or claude-ai no longer load or list skills, and Skill(anthropic-skills:*) allow rules now cover only skills synced from claude.ai. [3]
  • MCP protocol default (v2.1.292, v2.1.295). Local stdio servers and claude.ai connectors now negotiate MCP 2026-07-28 by default; MCP_PROTOCOL_NEGOTIATION=legacy opts out. [13][16]

Tips & Techniques

  • Re-tune effort for Opus 5.5. Opus 5.5 defaults to medium on the API, and old saved effort levels no longer carry over to it. Try the default first, raise it with /effort for hard tasks, and use Fable 5.1 when Opus 5.5 at higher effort still falls short. [1][18][19]
  • Run cheap subagents cheaply. Use the Agent tool's new effort parameter (or ask Claude for a low-effort subagent) for search and summarization fan-outs, and give long-running subagents an earlier autoCompactWindow. [13][17]
  • Audit your prompts for the new models. Run /doctor prompt-audit to find CLAUDE.md, skill and agent wording written for older models. [4]
  • Make guard hooks fail closed. For security-critical PreToolUse command/HTTP hooks, set onFailure: "block" so a crashed or timed-out hook can't silently let an action through. [16]
  • Vet mods before installing. Run claude plugin validate ./some-mod and read its hooks:/calls: lines, because a mod runs unsandboxed with your permissions. [21]

Recommended Default-Config Changes

  • Decide your starting permission mode explicitly. Auto mode is now the built-in start. If your team or a sensitive repo should start in Manual or acceptEdits, set permissions.defaultMode in settings rather than relying on the old default. [5][20]
  • Pin or gate models deliberately (admins). Use availableModelsMatch: "exact" if you want to approve each new model release before rollout, and deniedModels to block specific ones. Remove stale ANTHROPIC_DEFAULT_*_MODEL pins that hold you on older models unintentionally. [4][19]
  • Switch attribution off the simple way if you need to. Use "attribution": false only in files read by v2.1.281+ CLIs. Keep the object form in shared files. [2]
  • Set maxProseWidth if you work in very wide terminals. [3]
  • Move telemetry config out of project settings. OTel export variables in .claude/settings.json are now ignored. Set them in user or managed settings or the environment. [3]
  • Check gateways for 1M context. If your ANTHROPIC_BASE_URL gateway or cloud provider can't serve 1M, set /autocompact 200k or CLAUDE_CODE_DISABLE_1M_CONTEXT=1. [6][8]
