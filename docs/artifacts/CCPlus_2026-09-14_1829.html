Summary

No new model shipped this period — the news is a fresh batch of configuration surface, a plugin-tooling expansion, and a broad security-hardening and prompt-cache-stability pass. Releases v2.1.265 through v2.1.270 landed since the prior period's v2.1.263 (v2.1.264 was never tagged; v2.1.266 and v2.1.270 are pure regression fixes). [8] Headline additions: a maxEffortLevel setting that caps effort on every provider — including Bedrock, Vertex and Foundry [3][7]; claude plugin eval for scored, reproducible plugin eval suites [5]; a scriptable /output-style [name] command [5]; and several new environment variables and CLI flags. The security work tightens permission-rule handling around symlinked directories, tee/env -C, and ${VAR} secret redaction, and a large set of fixes restores prompt-cache reuse across resume, model switches, and MCP reconnects. CLI advanced v2.1.263 → v2.1.270.

What's New

Effort & system-prompt control

  • maxEffortLevel setting (v2.1.267). Caps the effort level on every provider, including Bedrock, Vertex and Foundry; set it top-level or per-model under modelSettings. Users can still pick a lower level, and the lowest cap from any scope wins. The settings docs confirm it requires v2.1.267 or later. [3][7]
  • --system-prompt-snapshot off (v2.1.267). Renders the system prompt fresh on every request instead of reusing the conversation's recorded prompt — useful while iterating on prompt text. [3]
  • effort: frontmatter now honored on pinned-effort models (v2.1.267). effort: on custom commands, skills, and subagents was being ignored on models whose default effort is still pinned (Opus 4.7, Opus 4.8, Fable 5); it is now respected. [3]

Plugin tooling

  • claude plugin eval (v2.1.269). Runs a plugin's eval suite against Claude Code and returns scored, reproducible results as a JSON + HTML report; see claude plugin eval --help. [5]
  • --json across the plugin CLI (v2.1.268). Added to claude plugin install, uninstall, update, enable and disable, plus errorDetails/noteDetails on each row of claude plugin list --json, and configDirectory in claude auth status --json. [4]
  • --plugin-dir can point at a folder of plugins (v2.1.265). Each child folder with a manifest loads, and children added or removed while running are picked up. [1]
  • /plugin takes effect on menu close (v2.1.268). Installing, enabling or disabling a plugin now applies when you close the menu — /reload-plugins is no longer needed afterward. [4]

Output styles, Bash diffs & new env vars

  • /output-style [name] (v2.1.269). Lists and switches output styles, including over Remote Control and in cloud and other headless sessions. [5]
  • bashEditDiffEnabled (v2.1.269). Adds a diff of the files a Bash command changed to the Bash tool result when the Bash tool handles file edits. [5]
  • New environment variables. CLAUDE_CODE_WEBFETCH_DEADLINE_MS (v2.1.268; WebFetch now fails after 300s by default, 0 disables the deadline) [4]; CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS (1–256, raises the Workflow tool's per-run concurrent-agent limit for inference-bound fan-outs), OTEL_METRICS_INCLUDE_REPOSITORY (tags OpenTelemetry metrics/events with vcs.* attributes), CLAUDE_CODE_GATEWAY_MODEL_DISCOVERY_TIMEOUT_MS (extends the LLM-gateway /v1/models discovery timeout, default 3s), and CLAUDE_CODE_BG_TASKS_REPORT_RUNNING=0 (restores the old "waiting for your input" behavior while background agents run) all arrived in v2.1.269. [5]

Behavior & provider parity changes

  • Task-tracking tools scope made explicit (v2.1.268). TaskCreate/Get/Update/List and TodoWrite are now offered only on Claude 3.x, Opus 4.0–4.7, Sonnet 4.0–4.6, and Haiku 4.5; set CLAUDE_CODE_ENABLE_TODO_TOOLS=1 to enable them elsewhere. This refines the v2.1.233 removal on newer models with a concrete model list. [4]
  • WebFetch rules no longer cover Artifact reads (v2.1.268). Plain WebFetch deny/ask rules no longer apply to Artifact tool reads and updates — use an Artifact rule (or WebFetch(domain:claude.ai)) to block or gate them. [4]
  • Non-interactive cd now persists (v2.1.265). Non-interactive sessions (-p with stream-json input, Agent SDK, cloud sessions) no longer reset the shell working directory at each new user message; a cd persists across turns. [1]
  • MCP http falls back to SSE (v2.1.265). Servers configured as http that only speak the legacy HTTP+SSE transport now connect, as the MCP spec describes. [1]
  • 1 GB cap on tool results saved to disk (v2.1.265). The in-conversation preview now says when a saved file was truncated. [1]
  • Cloud-provider parity (v2.1.268). Bedrock, Vertex and Foundry sessions now deliver environment/model/settings as attachments and keep the tool list byte-stable across a conversation, matching first-party sessions. [4]
  • Gateway administration (v2.1.268). A pricing: block in gateway.yaml now propagates rates to signed-in clients via managed settings so /cost and telemetry match the spend meter; the new gatewayInternalNetworks managed setting lets admins allow /login from their own public IPv4 block; and an empty access_control.allow_cidrs now triggers a startup warning. [4]
  • Self-hosted runner --remove-session-state (v2.1.268). Optionally deletes each session's per-session directories under <base-dir>/_sessions/ when the session ends. [4]

Security hardening

  • Symlinked-directory deny/ask rules (v2.1.268). Deny and ask rules on symlinked directories (/etc, /tmp, /var on macOS; /bin on Linux) now apply when a path is given by its real location, and Bash commands no longer ignore deny rules written on a symlinked path spelling. [4]
  • Deny rules through env -C/eval and tee (v2.1.268–269). A Read/Edit deny rule now applies even when an env -C, eval, or similar command shares the line [4]; and Edit() deny rules and the write-path check now cover the file a Bash tee writes, so a Bash(tee:*) allow rule no longer reaches destinations outside the working directories. [5]
  • Secret redaction (v2.1.268). Plugin and marketplace errors no longer print a token or password from a git source URL, and /mcp, /plugin, claude mcp list/get and MCP login errors no longer show secrets resolved from ${VAR} placeholders. [4]
  • !-negation rules scoped to their source (v2.1.269). A deny or ask rule starting with ! now applies only within the settings source that wrote it, and a bare ! negation is ignored. [5]
  • PermissionRequest hooks fire in --print mode (v2.1.268). [4] Plugin archives extracted for a session are also no longer readable by other local users, and no longer keep world-writable bits from the archive (v2.1.269). [5]

Prompt-cache stability

  • A large prompt-cache-reuse pass (v2.1.265, v2.1.267, v2.1.269). Fixes stop resumed sessions, foreground-spawned subagents, model switches with /model, MCP reconnects, and --system-prompt/--append-system-prompt sessions from rewriting the tool list or system-prompt prefix and breaking cache reuse; mid-session MCP and plugin tools are now delivered as deferred definitions on supported models rather than rewriting the tool block. [1][3][5]

Tips & Techniques

  • Bound cost and latency with maxEffortLevel. Set a cap at the user or managed-settings level to keep every provider (including Bedrock/Vertex/Foundry) under a ceiling; combine with per-model entries under modelSettings when only some models should be capped. [3][7]
  • Iterate on system-prompt text quickly. Launch with --system-prompt-snapshot off so each request re-renders the prompt, then remove the flag once the text is settled. [3]
  • Gate plugin quality in CI. Wire claude plugin eval into your pipeline and parse its JSON report to fail builds on regressions before publishing. [5]
  • Switch output styles in headless runs. Use /output-style [name] from cloud, Remote Control, and other headless sessions instead of relying on interactive menus. [5]
  • See what a Bash step changed. Enable bashEditDiffEnabled so Bash commands that edit files return a diff in the tool result. [5]
  • Scale inference-bound workflows. Raise CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS (up to 256) for fan-outs that are limited by model throughput rather than local CPU. [5]
  • Tame slow WebFetch targets. Set CLAUDE_CODE_WEBFETCH_DEADLINE_MS to shorten the new 300s deadline (or 0 to turn it off) for endpoints that hang. [4]

Recommended Default-Config Changes

  • Add a maxEffortLevel ceiling. Put a sensible cap in user or managed settings to bound spend across all providers; teams on Bedrock/Vertex/Foundry benefit most since the cap now reaches those providers. [3][7]
  • Move artifact gating from WebFetch to Artifact rules. If you relied on a WebFetch deny/ask rule to gate Claude reading artifacts, switch to an Artifact rule (or WebFetch(domain:claude.ai)) — WebFetch rules no longer cover Artifact reads/updates. [4]
  • Re-check your todo-tools posture. With the model list now explicit, set CLAUDE_CODE_ENABLE_TODO_TOOLS=1 only where you still want TaskCreate/TodoWrite on newer models. [4]
  • Audit permission rules that leaned on old gaps. Symlinked-directory deny rules, tee writes, and env -C/eval lines are now honored, and !-negation rules apply only within their own settings source — review any allow rules or split rule sets that depended on the previous behavior. [4][5]
  • Set a WebFetch deadline for slow environments. Add CLAUDE_CODE_WEBFETCH_DEADLINE_MS to your env if you routinely fetch endpoints that can hang. [4]
