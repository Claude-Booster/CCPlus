Summary

That moves the CLI from v2.1.310 to v2.1.316; there are no GitHub Release tags for v2.1.313 or v2.1.315. [6] On current models, ultrathink now runs its turn at xhigh effort through Anthropic's API (v2.1.311), and v2.1.316 adds CLAUDE_CODE_DISABLE_ULTRATHINK to turn the keyword off. [1][4] Two new controls landed: permissions.blockWritesOutsideWorkingDirectories stops the file tools writing outside the working directories in every mode (v2.1.314), and CLAUDE_CODE_SUBAGENT_EFFORT sets the effort subagents use by default (v2.1.316). What's New

Models, effort & deprecations

  • Fast mode on Opus 4.8 deprecated (v2.1.316). It was deprecated as of October 30, 2026 and will be removed on November 30, 2026. After that date, fast-mode requests on Opus 4.8 return an error instead of falling back to standard Opus 4.8. The release notes say to move to Opus 5.5 to keep the speedup. [4]
  • ultrathink means xhigh effort (v2.1.311). In the interactive terminal, the keyword now runs its turn at xhigh effort on Opus 5.5, Sonnet 5.5, Haiku 5.5 and Fable 5.1 through Anthropic's API. If you type it while Claude is working, it raises effort for the rest of that turn. The rainbow highlight now appears only where the keyword can raise effort. VS Code got the same behavior in v2.1.316, and CLAUDE_CODE_DISABLE_ULTRATHINK turns the keyword off. [1][4]
  • CLAUDE_CODE_SUBAGENT_EFFORT (v2.1.316). It sets the effort subagents run at when nothing else names one. Without it, they inherit the session's effort. [4]
  • Effort caps no longer break sessions (v2.1.314). If an admin caps a model's effort, Claude Code now lowers the effort, retries, and says which level it is using. Before, every turn failed with "Invalid effort level". [3]
  • [1m] suffix dropped where it does nothing (v2.1.311). Model names and IDs no longer show the suffix or its label on models where it has no effect. The suffix is still accepted. [1]

Permissions, auto mode & security

  • permissions.blockWritesOutsideWorkingDirectories (v2.1.314). When it's on, Write, Edit and NotebookEdit refuse paths outside the working directories in every permission mode. It is the write-side counterpart of permissions.blockReadsOutsideWorkingDirectories, which was added in v2.1.257. [3][8]
  • Server-managed settings apply without a prompt (v2.1.316). For Team and Enterprise logins, settings fetched from Anthropic's API now apply without an approval prompt. A stored copy that fails verification is refused. [4]
  • Managed-settings fixes (v2.1.314). If forceRemoteSettingsRefresh was set only in remote managed settings, it stopped applying once the stored copy expired, so sessions could start without policy; that is fixed. A settings file excluded with --setting-sources no longer supplies auto-mode rules or saved permission consents. Claude's file tools now ask before editing the local copy of server-managed settings. [3]
  • Hooks and the Monitor tool (v2.1.314). Hooks that match Bash now also run on shell commands the Monitor tool starts. They can block or ask, but can't approve or rewrite those commands. Hook if conditions such as Monitor(tail *) now match Monitor's shell commands the same way Bash(tail *) matches Bash. [3]
  • Hook limits. Prompt and agent hooks now run at most 24 at a time per session, subagents included, plus at most 12 that have waited past their event's timeout. A timeout under 1 second counts as 1 second (v2.1.312) [2]. PreCompact hook output is now cut at 10,000 characters per hook (v2.1.314). [3]
  • Auto mode fixes. A managed autoMode.allow list without "$defaults" no longer gets the built-in exceptions back from a host app's --settings, a first rule added in /permissions, or /auto-mode-setup (v2.1.316) [4]. Auto mode no longer reports a call as blocked when its safety check gave no verdict. The /permissions review tab is renamed "Recently blocked" and refuses to approve a call you can't read in full (v2.1.314). [3]
  • Other security fixes. --restricted sessions no longer upload files from outside the working directories when a Read allow rule covers them (v2.1.316) [4]. Sandbox protections now apply to a worktree entered by claude -p --resume/--continue. With CI set, claude ultrareview and claude remote-control refuse an untrusted folder at once instead of asking, and /ultrareview checks workspace trust before it runs git (v2.1.314). [3]
  • DISABLE_COMPACT is one-way (v2.1.311). In settings files and a mod's $.env.set, it can now only turn compaction off, not back on. [1]

Context & compaction

  • Idle compaction on more surfaces (v2.1.314). VS Code and Claude Desktop's Code tab now summarize a 200K+ token conversation left idle, and use the summary on your next message if the prompt cache has expired. Idle compaction now also runs for subscribers with telemetry off, and on Bedrock, Vertex, Foundry and LLM gateways once the 1-hour prompt cache is on. [3]
  • Subagent autoCompactWindow works (v2.1.312). A subagent's autoCompactWindow now lowers the window set by CLAUDE_CODE_AUTO_COMPACT_WINDOW; before, it had no effect. It still never raises that window. [2]
  • Over-200K requests in standard-context sessions (v2.1.311). These sessions used to stop with "Usage credits required for 1M context". Claude Code now compacts and continues. Compaction also asks again for a summary when the model's reply has none. [1]
  • Safer writes to large instruction files (v2.1.312). Write no longer overwrites a very large CLAUDE.md, rules file or @-included file in a subdirectory after seeing only its start. It asks Claude to read the whole file or edit it in place. [2]
  • Memory and subagent fixes (v2.1.311). Claude no longer sees stale MEMORY.md or CLAUDE.md content right after automatic compaction. SubagentStop hooks now run once when a subagent finishes, not about twice a minute. Subagents can use MCP tools from servers that finish connecting after the subagent starts. [1]

Providers & gateways

  • Signed model catalog (v2.1.311). On Bedrock, Mantle, Vertex and Foundry, Claude Code now loads model settings from a signed file on downloads.claude.ai. Set CLAUDE_CODE_MODEL_CATALOG=off to turn this off, for example on networks that block that host. [1]
  • Shorter prompt for model names Claude Code doesn't recognize (v2.1.312). On Bedrock, Vertex, Foundry and Mantle, custom deployment names and inference-profile ARNs now get the shorter system prompt, even when they front Sonnet or Haiku. Set CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0 to keep the full prompt. Automatic model switches after a flagged message now cover these names too; set CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK=1 to turn that off. [2][7]
  • Fallback to older models. On Foundry, if the resource has no deployment for the default Sonnet, Opus or Haiku, Claude Code falls back to an older model of that family (v2.1.314). On Vertex and Bedrock, the sonnet/opus/haiku aliases now switch to an older model, instead of erroring mid-session, when the newest isn't available to the account or region (v2.1.316). [3][4]
  • Gateway compatibility (v2.1.314). Claude Code resends a request without a beta header the gateway refused by name, and without tool search when the gateway rejects tool_reference blocks. Model IDs written with a dot, such as claude-opus-4.8, are no longer treated as an older model. [3]
  • Claude apps gateway. oidc.user_id_claim to identify people by a claim other than sub, such as Entra ID's oid (v2.1.312) [2]. Per-upstream IdP groups and Bedrock guardrail_trace (v2.1.314) [3]. pooled_budget group budgets, managed.policy_mode: layered, Bedrock guardrail.input_tagging, and checks of every requested model against availableModels/deniedModels/models (v2.1.316). [4]
  • TLS (v2.1.314, v2.1.316). Fixed UNABLE_TO_GET_ISSUER_CERT errors with cross-signed renewed roots. CLAUDE_CODE_DISABLE_LOOPED_CROSS_CERT_DROP keeps looped cross-certificates for private CAs that need them. [3][4]

Tooling, observability & other

  • claude_code.safety_event removed (v2.1.312). Claude Code no longer sends the OpenTelemetry event that v2.1.307 added. OTel mcp_server.name now reports the real name of fixed-URL remote MCP servers from official Anthropic-marketplace plugins, instead of custom. [2]
  • Headless output. claude -p now prints the error and exits 1 when startup fails, instead of exiting 0 with no output (v2.1.314) [3]. --output-format json and stream-json now escape DEL, C1 control and Unicode format characters as \uXXXX; the parsed values are unchanged (v2.1.311). [1]
  • Bash tool shell (v2.1.314). It clears any inherited which alias or function, so which is the system command or the zsh builtin. FORCE_HYPERLINK=false/no/off now turns hyperlinks off. [3]
  • Self-hosted runner (v2.1.311). --hold-idle-file and --max-hold-min keep an idle session alive while your host reports processes it left running. [1]
  • VS Code. Sessions now start with DISABLE_TELEMETRY set while VS Code's telemetry setting is off (v2.1.311) [1]. You can sign in to a Claude apps gateway from the chat panel (v2.1.316). [4]
  • Misc. Usage messages say "5-hour limit" instead of "session limit" (v2.1.312) [2]. Ctrl+R matches text inside collapsed [Pasted text] pills, and the .trash folders for skills and plugins are capped at about 1,024 entries (v2.1.314) [3]. /code-review findings cards appear in cloud and Remote Control sessions (v2.1.316). [4]

Tips & Techniques

  • Use ultrathink for one hard turn. On the 5.5 models and Fable 5.1 it now runs that turn at xhigh. You can also type it mid-turn to raise effort for the rest of the turn. [1]
  • Pair session effort with subagent effort. Keep the main session at high effort and set CLAUDE_CODE_SUBAGENT_EFFORT lower for fan-out search agents. This saves tokens where depth matters less. [4]
  • Use subagent autoCompactWindow. Since v2.1.312 it lowers the global window, so long-running research subagents can compact earlier than the main session. [2]
  • Check scripts that rely on claude -p exit codes. Startup failures now exit 1 with an error message, so CI that treated empty output as success will now see the failure. [3]

Recommended Default-Config Changes

  • Move off fast mode on Opus 4.8 before November 30, 2026. If /fast or your settings pin Opus 4.8, switch to Opus 5.5. After that date, fast requests on 4.8 will fail. [4]
  • Consider "permissions": {"blockWritesOutsideWorkingDirectories": true}. It fits well for auto mode and unattended runs, together with blockReadsOutsideWorkingDirectories. Use /add-dir for any other folders a task really needs. [3][8]
  • Set CLAUDE_CODE_SUBAGENT_EFFORT in your settings env block if you run many subagents and want their cost independent of the session's effort. [4]
  • Bedrock, Vertex and Foundry with custom deployment names: if answer quality drops after upgrading, set CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0 to restore the full prompt. If your network blocks downloads.claude.ai, set CLAUDE_CODE_MODEL_CATALOG=off. [1][2][7]
  • OTel dashboards: remove queries built on claude_code.safety_event, which is no longer sent as of v2.1.312. [2]
  • Admins: if your organization caps a model's effort (for example with maxEffortLevel), upgrade to at least v2.1.314 so capped sessions retry at a lower level instead of failing. [3]
