Summary

The week since v1.2 (Aug 10) brought no new models but several default-behavior and config changes across CLI v2.1.227–v2.1.233[1]. Two stand out. First, subagent forking is now on by default: a subagent_type: "fork" subagent inherits the full conversation and prompt cache, and non-teammate agent spawns in interactive sessions now run in the background by default[2]. Second, the built-in Todo / task-tracking tools (TaskCreate/Get/Update/List and TodoWrite) are no longer available on Opus 4.8, Sonnet 5, Fable 5, Mythos 5, and newer models; set CLAUDE_CODE_ENABLE_TODO_TOOLS=1 to bring them back[3]. Session-to-session workflow got friendlier too—type @ to mention another Claude session by name, and SendMessage now delivers to a bare name that matches one live session[2]. There is broad new GitLab support (plugin marketplaces, token redaction, and merge-request worktrees), the Write tool now lets newer models overwrite an unread file to match Edit, and /code-review at high/xhigh/max now runs in the background like the other levels[2][3][5]. The current CLI is v2.1.233 (Aug 14)[1]. Every claim below is cited; sources are listed at the bottom.

What's New

Highlights from Claude Code CLI v2.1.227 → v2.1.233 (August 10–14, 2026)[1].

  • Subagent forking is on by default (v2.1.232, Aug 13). A subagent_type: "fork" subagent inherits the parent's full conversation and prompt cache, and non-teammate agent spawns in interactive sessions now run in the background by default[2].
  • Todo / task-tracking tools removed on newer models (v2.1.233, Aug 14). TaskCreate, TaskGet, TaskUpdate, TaskList, and TodoWrite are no longer offered to Opus 4.8, Sonnet 5, Fable 5, Mythos 5, and newer models; set CLAUDE_CODE_ENABLE_TODO_TOOLS=1 to re-enable them[3].
  • Mention another session with @ (v2.1.232, Aug 13). Typing @ in the prompt lets you mention another Claude session by name; Claude then uses SendMessage to reach it directly. SendMessage now delivers to a bare name that exactly matches one live session instead of asking you to confirm a [ref] first, and interactive sessions on one machine keep unique names (a clashing name gets a name-word-word variant)[2].
  • GitLab support (v2.1.232–v2.1.233, Aug 13–14). Plugin marketplaces now clone bare gitlab.com repo URLs (including nested subgroups) like GitHub URLs; GitLab token families are redacted (routable glpat-/gldt- tokens are fully redacted) and the glab CLI config gets the same sandbox protection as gh[2]. In v2.1.233, the --worktree flag and the claude agents view accept GitLab merge-request URLs (MRs display as !N)[3].
  • Write tool matches Edit's overwrite rules for newer models (v2.1.228, Aug 11). Newer models can overwrite an existing file they haven't read this session; older models still require reading it first[5].
  • /code-review at high, xhigh, and max now runs in a background agent (v2.1.232, Aug 13), matching the other effort levels[2].
  • Plugin marketplace command sources (v2.1.229, Aug 12). A local command (for example, an IDE) prints the plugin directory, which is re-resolved each session and applied without a restart; mode: "link" uses the directory in place[4].
  • New /config rows and settings aliases (v2.1.232, Aug 13). /config gained "Dialog expiry" and "Messages from your other sessions" (cross-session inbound accept/hold/refuse) rows, and additionalMarketplaces / allowedMarketplaces are now accepted as friendlier aliases for extraKnownMarketplaces / strictKnownMarketplaces[2][6].
  • Nested git repositories require their own trust (v2.1.232, Aug 13). A nested repo no longer inherits trust from a parent directory—each requires its own confirmation[2].
  • Tighter defaults for /commit-push-pr (v2.1.229, Aug 12). git/gh commands with dangerous flags (--force, --amend, --no-verify, etc.) are no longer auto-approved[4].
  • New env-var controls (v2.1.233, Aug 14). CLAUDE_CODE_TOOL_MEMORY_LIMIT opt-in memory cgroups for Bash commands on Linux (so a runaway build can't stall the session), and CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS to tune the WebFetch URL cache (default unchanged at 15 minutes)[3].
  • Notification hooks fixed under Desktop / VS Code (v2.1.233, Aug 14). Notification hooks now fire for permission prompts when running under Claude Desktop or VS Code[3]. Also this period: ListAgents marks disconnected Remote Control sessions as offline and labels cloud sessions as cloud, and claude remote-control --continue resumes the most recent Remote Control session (v2.1.229)[4].
  • MCP OAuth sign-in fix for pre-registered clients (v2.1.231, Aug 13). Fixed MCP OAuth sign-in failing with a redirect-URI mismatch for servers that use a pre-registered OAuth client, such as Slack[1].

Tips & Techniques

  • Hand a subtask your full context with a fork. Because subagent_type: "fork" now inherits the whole conversation and warm prompt cache, use it when a subagent needs everything you already know rather than a fresh brief; the fork also runs in the background by default in interactive sessions (v2.1.232)[2].
  • Route work between your own sessions by name. Type @ to mention a live session and Claude will SendMessage it directly—handy for coordinating a long-running build session and an interactive one on the same machine (v2.1.232)[2].
  • Cap Bash memory on Linux for flaky builds. Set CLAUDE_CODE_TOOL_MEMORY_LIMIT so a memory-hungry command is contained in a cgroup instead of stalling the whole session (v2.1.233)[3].
  • Speed up large fan-outs. Same-prefix sibling agents in a workflow are now staggered so later agents read the cached prompt prefix instead of re-paying for it; set CLAUDE_CODE_WORKFLOW_PREFIX_STAGGER_MS=0 to disable (v2.1.229)[4].
  • Keep TodoWrite if your workflow depends on it. If your prompts or automation lean on the task/todo tools, export CLAUDE_CODE_ENABLE_TODO_TOOLS=1; otherwise newer models will simply plan inline without them (v2.1.233)[3].

Hacks

Lesser-known but documented power-user techniques (each corroborated by the release notes and docs).

  • Work a GitLab MR from a worktree. Pass a GitLab merge-request URL to --worktree (or open it from claude agents, where it shows as !N) to check out and iterate on it just like a GitHub PR (v2.1.233)[3].
  • Serve a plugin directory straight from your IDE. A marketplace command source runs a local command that prints the plugin directory, re-resolved each session without a restart—use mode: "link" to develop against a live checkout (v2.1.229)[4].
  • Install a freshly published plugin without a manual refresh. /plugin install plugin@marketplace now refreshes the marketplace first, so newly published plugins install without running a marketplace update yourself (v2.1.232)[2].

Recommended Default-Config Changes

Models and permission defaults are unchanged since v1.1, so the starter settings.json still holds. The important change this period is behavioral rather than a new key: on newer models the task/todo tools are gone by default, and a few commands got safer defaults. Decide whether any of the following applies to you.

{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "opusplan",
  "effortLevel": "high",
  "crossSessionInbound": "hold",
  "dialogExpiry": "5m"
}

Unchanged from v1.2. The new movement is in behavior and environment variables, not in these keys.

Decide on the task/todo tools

  • On Opus 4.8, Sonnet 5, Fable 5, Mythos 5, and newer models the task/todo tools (TaskCreate/Get/Update/List, TodoWrite) are no longer offered. If your CLAUDE.md, hooks, or automation reference them, add CLAUDE_CODE_ENABLE_TODO_TOOLS=1 to your environment (or the env block in settings.json); otherwise remove those references and let the model plan inline[3].

Review your automation defaults

  • /commit-push-pr no longer auto-approves dangerous git/gh flags (--force, --amend, --no-verify, …). If you relied on that command running unattended, expect an approval prompt for those flags now (v2.1.229)[4].
  • Nested repositories each need their own trust confirmation, so scripted runs that cd into a submodule or vendored repo may now pause for trust (v2.1.232)[2].
  • Marketplace keys have friendlier aliases. New configs can use additionalMarketplaces / allowedMarketplaces in place of extraKnownMarketplaces / strictKnownMarketplaces; both spellings are accepted (v2.1.232)[2][6].

Good habits

  • Keep the CLI current—v2.1.233 is the latest and this window closed several PowerShell, Windows Git Bash symlink, and Linux sandbox permission-bypass vectors, and reverted an over-broad v2.1.232 Bash permission change (narrower version to return later)[1][2][3].
  • Skills synced from claude.ai are now sandboxed (they don't shadow local commands/MCP prompts, their bodies don't run ! commands or expand @ files on your machine); still review any synced skill before trusting it (v2.1.228)[5].
  • If you use Notification hooks under Claude Desktop or VS Code, upgrade to v2.1.233—those hooks now fire on permission prompts again[3].
