Summary

The two months since the v1.0 baseline (Jun 4) brought the biggest changes yet — most of all, two new default models. Claude Sonnet 5 shipped in CLI v2.1.197 (Jun 30) as the new default model in Claude Code, with a native 1M-token context and introductory pricing of $2/$10 per Mtok through Aug 31[2][4]. Claude Opus 5 followed in v2.1.219 (Jul 24) as the new default Opus model (claude-opus-5), excelling at software engineering, knowledge work, and problem-solving and coming close to Fable 5's intelligence at about half the price[3][5]. Alongside the models, several defaults changed: the "default" permission mode was renamed Manual[6], subagents now run in the background so Claude keeps working while they execute[7], auto mode no longer needs an opt-in on Bedrock/Vertex/Foundry[8], and Claude in Chrome reached general availability[7]. New configuration surfaces landed too — /config key=value, parameter-scoped permission rules like Agent(model:opus), a /dataviz skill, and a screen-reader mode. The current CLI is v2.1.223 (Aug 6)[1]. Every claim below is cited; sources are listed at the bottom.

What's New

Highlights from Claude Code CLI v2.1.163 → v2.1.223 (June 4 – August 6, 2026)[1].

  • Claude Sonnet 5 — new default model (v2.1.197, Jun 30). Native 1M-token context; introductory pricing $2/$10 per Mtok through Aug 31 (standard $3/$15). Requires CLI v2.1.197+[1][2][4].
  • Claude Opus 5 — new default Opus model (v2.1.219, Jul 24). The opus alias now resolves to claude-opus-5 on the Anthropic API; 1M context, priced $5/$25 per Mtok (Fast mode ~2.5× speed at $10/$50). It is the default on Claude Max and the strongest model on Pro, built for software engineering, knowledge work, and problem-solving and approaching Fable 5 capability at about half the price. Requires CLI v2.1.219+[1][3][5][9].
  • Default permission mode renamed to "Manual" (v2.1.200, Jul 3), across the CLI, --help, VS Code, and JetBrains; --permission-mode manual and "defaultMode": "manual" are accepted. In the same release, AskUserQuestion dialogs no longer auto-continue by default — opt into an idle timeout via /config[6].
  • Subagents run in the background by default (v2.1.198, Jul 1), so Claude keeps working while they run and is notified when they finish. Background agents launched from claude agents commit, push, and open a draft PR when they finish code work in a worktree[7].
  • Claude in Chrome is generally available (v2.1.198, Jul 1)[7].
  • Auto mode without opt-in on cloud providers (v2.1.207, Jul 11) — auto mode is now available on Bedrock, Vertex AI, and Foundry without CLAUDE_CODE_ENABLE_AUTO_MODE; disable via disableAutoMode in settings[8].
  • Organization default models (v2.1.196, Jun 29) — admins set an org default in the console; it appears as "Org default" (or "Role default") in /model until you pick your own[1].
  • /dataviz skill (v2.1.198) — chart and dashboard design guidance with a runnable color-palette validator[7].
  • Screen reader mode (v2.1.208, Jul 14) — opt-in plain-text rendering via claude --ax-screen-reader, CLAUDE_AX_SCREEN_READER=1, or "axScreenReader": true[1].
  • /review is now an alias of /code-review (v2.1.223, Aug 6), which reviews the current diff or a PR (/code-review <level> <pr#>); use /code-review ultra for a deep cloud review. /code-review also runs as a background subagent now (v2.1.218)[1].
  • Nested subagents (v2.1.219) — subagents can spawn their own subagents up to depth 3 by default; set CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1 to disable nesting. Fan-out caps from earlier releases remain in effect: 20 concurrent (v2.1.217, CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS) and 200 per session (v2.1.212, CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION)[1].
  • ! bash commands trigger a response (v2.1.186, Jun 22) — the output of a ! shell command now prompts Claude to respond automatically; set "respondToBashCommands": false to keep the previous context-only behavior[1].
  • Bash-permission security hardening — a run of releases (v2.1.214, v2.1.221, v2.1.222, v2.1.223) closed permission-check bypasses (e.g. commands hiding parts of themselves via tabs/invisible Unicode or zsh [[ ]] constructs) and tightened worktree isolation so isolated sessions can't run destructive git against the main checkout. Keeping current is a security update, not just a feature one[1].

Tips & Techniques

  • Set any setting from the prompt with /config key=value (v2.1.181) — e.g. /config thinking=false. Works in interactive, -p, and Remote Control; run /config --help for the shorthand keys[1].
  • Scope permission rules by tool parameter (v2.1.178) — the new Tool(param:value) syntax matches a tool's input parameters (with * wildcard), so Agent(model:opus) can block Opus subagents while allowing others[1].
  • Let subagents fan out while you keep working. Because subagents now run in the background, delegate exploratory or parallelizable work and watch progress in claude agents; the Notification hook fires agent_needs_input / agent_completed events you can wire up[7].
  • Fork a conversation into its own background session with /fork (v2.1.212) — it copies your conversation into a new claude agents row while you keep working; the in-session subagent it used to launch is now /subtask[1].
  • Recover from a mistaken /clear — /rewind can now resume a conversation from before /clear was run (v2.1.191)[1].
  • Pick the right model for the work. opus now resolves to Opus 5 (complex reasoning and software engineering), sonnet to Sonnet 5 (daily coding); opusplan still plans on Opus and executes on Sonnet, and fable selects Fable 5 for your hardest, longest-running tasks[9].
  • Trim CLAUDE.md automatically. /doctor now proposes cutting checked-in CLAUDE.md content that Claude could derive from the codebase (v2.1.206), keeping the file lean[1].
  • Enable screen reader mode if you use assistive tech — claude --ax-screen-reader renders plain text and announces permission-mode changes and deletions aloud[1].

Hacks

Lesser-known but documented power-user techniques (each corroborated by the release notes and docs).

  • Pin a model version instead of an alias. Aliases move over time; to lock a version use the full name (claude-opus-5) or set ANTHROPIC_DEFAULT_OPUS_MODEL / ANTHROPIC_DEFAULT_SONNET_MODEL. This also lets you select a newer model where an alias still resolves to an older one (e.g. Sonnet on Bedrock)[9].
  • Cap runaway delegation and search loops. Tune CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS, CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION, and CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION to bound fan-out and web-search budgets per session (v2.1.212, v2.1.217)[1].
  • Cap unattended spend. --max-budget-usd now also stops background subagents: once the cap is hit, new spawns are denied and running background agents are halted (v2.1.217)[1].
  • Suppress mobile push while you're at the machine by pointing CLAUDE_CLIENT_PRESENCE_FILE at a marker file (v2.1.181)[1].
  • Map jj to Escape in vim mode with the vimInsertModeRemaps setting (v2.1.208)[1].

Recommended Default-Config Changes

An updated starter ~/.claude/settings.json (user scope) reflecting the new model and permission defaults. On a managed/Enterprise machine, managed settings take precedence and may restrict models or permissions — these are user-level suggestions that apply where policy allows[10][9].

{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "opusplan",
  "effortLevel": "high",
  "outputStyle": "default",
  "statusLine": { "type": "command", "command": "~/.claude/statusline.sh" },
  "permissions": {
    "allow": [
      "Bash(git status)", "Bash(git diff *)", "Bash(git log *)",
      "Bash(npm run lint)", "Bash(npm run test *)"
    ],
    "deny": [
      "Read(./.env)", "Read(./.env.*)", "Read(./secrets/**)", "Bash(curl *)"
    ]
  },
  "attribution": { "commit": "🤖 Generated with Claude Code" }
}

What changed since v1.0: the opus/sonnet aliases now resolve to Opus 5 / Sonnet 5 on the Anthropic API[9], so opusplan gives you Opus-5 planning with Sonnet-5 execution. The keys above are otherwise stable in the settings schema[10].

Decide your permission posture deliberately

  • The base mode is now called "Manual" (formerly "default"): every tool use is confirmed. Keep it for unfamiliar repos; relax to acceptEdits for trusted edit-heavy work, or auto mode when you want the classifier to adjudicate[6].
  • Auto mode is now on by default on Bedrock/Vertex/Foundry. If your org needs manual approval there, set "disableAutoMode": true in settings[8][10].
  • Constrain models org-wide with availableModels plus enforceAvailableModels, which also constrains what "Default" can resolve to[10].

Built-in slash commands worth knowing

  • /config key=value — set any setting inline; /config --help lists keys[1]
  • /code-review (and its alias /review) — review the diff or a PR; /code-review ultra for a cloud review[1]
  • /fork & /subtask — branch a conversation into a background session, or delegate an in-session subtask[1]
  • /rewind — step back, including across a /clear[1]
  • /doctor — full setup checkup that can propose CLAUDE.md trims and fix issues[1]
  • /model, /effort — switch model / reasoning depth[9]

Good habits

  • Keep the CLI current — recent releases include real permission-bypass and worktree-isolation security fixes, not just features[1].
  • Delegate parallelizable work to background subagents, then review their diffs and PRs before merging[7].
  • Scope tasks tightly, commit frequently, and pin a model version when you need reproducibility[9].
