Summary

There was no new model this week, but several defaults changed. Releases v2.1.299–v2.1.303 landed (there are no v2.1.297 or v2.1.298 tags), so the CLI moved from v2.1.296 to v2.1.303. [8][9] The biggest change is idle compaction. The terminal now compacts a conversation of 200K+ tokens that has sat idle for about 54 minutes, just before its one-hour prompt cache expires, so your next message doesn't pay to reprocess the whole thing (v2.1.299). It can be tuned or turned off. [1][4][6] Permissions got stricter in two places. MCP allow rules now match only the server they name, and the updatedInput that hooks return is now validated like Claude's own tool input (v2.1.299–300). [1][2][7] Fork subagents are now on by default in claude -p, the Agent SDK, the desktop app and VS Code, and claude -p on third-party providers goes back to starting in default mode rather than auto (v2.1.302). [4] Smaller additions include CLAUDE_CODE_AUTO_MODE_MODEL, CLAUDE_CODE_DISABLE_FILE_MENTIONS, gzip for large API requests, new OpenTelemetry attributes, and a % motion in vim mode. [1][2][3][4]

What's New

Context, compaction & cost

  • Idle compaction (v2.1.299). In the terminal, a conversation of at least 200K tokens that sits idle for about 54 minutes is compacted before its one-hour prompt cache expires. That way, coming back to it doesn't reprocess the full context. CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS changes the 200K threshold, and "idleCompaction": false in settings.json turns it off. v2.1.302 added an Idle compaction row to /config, and the notice shown after an idle compaction now explains how to turn it off. [1][4][6]
  • Path-only @ mentions (v2.1.299). CLAUDE_CODE_DISABLE_FILE_MENTIONS stops Claude Code from inlining the files you @-mention. Claude gets their paths instead and reads them with its file tools. Separately, @-mentioned PDFs no longer keep their bytes in the session transcript. [1][6]
  • Smarter model switching (v2.1.301). When you switch to a model with a smaller context window, a conversation that is too long for the new model is now summarized by the previous model first. A fix in the same release stops that summary from spending usage credits without asking. [3]
  • Gzip request bodies (v2.1.300). Large requests to api.anthropic.com are now gzip-compressed even with telemetry off. Set CLAUDE_CODE_GZIP_REQUEST_BODIES=0 to turn this off. [2][6]
  • /usage warnings (v2.1.299). /usage now flags max effort, workflows, always-on context and large tool results. [1]

Permissions, hooks & auto mode

  • MCP allow rules match only the server they name (v2.1.299). mcp__a no longer allows a server named a__b or a_. Agent tools: lists changed the same way. For a server whose normalized name contains __, write mcp__<whole name>__*. Deny and ask rules for such servers now apply correctly too. The permissions docs describe the same rule. [1][7]
  • Hook updatedInput is validated (v2.1.300). When a PreToolUse or PermissionRequest hook rewrites a tool's input, Claude Code now drops unknown keys, and a rewritten input that the tool rejects denies the call. [2]
  • Hook ordering and failure behavior (v2.1.299). UserPromptSubmit hooks now run before a skill or custom slash command expands, so a hook that blocks the prompt also stops that command's embedded shell lines. An action a plugin hook could block is now refused, not let through, when the hook can't receive it or can't return an answer. Plan mode no longer runs a write that a PreToolUse hook or a mod's tool.check allowed. [1]
  • Concurrency cap on prompt/agent hooks (v2.1.302). At most 12 prompt or agent hooks for the same event run at once, and the rest wait their turn. Agent hooks now honor their model field, and aliases such as haiku resolve (v2.1.300). [4][2]
  • Auto mode classifier model (v2.1.302). CLAUDE_CODE_AUTO_MODE_MODEL chooses the model that the client-side auto mode classifier uses. It has no effect on the server-side classifier. With the server-side classifier, a conversation too long for the safety check is now compacted, instead of every checked tool call being denied. [4]
  • claude -p starts in default mode on third-party providers (v2.1.302). claude -p and Agent SDK sessions with no permission mode set now start in default mode on third-party providers, with telemetry off, or on a fresh install. This partly reverses the v2.1.285 change reported in v1.9. --permission-mode auto still selects auto mode. [4]
  • rm prompts are less noisy (v2.1.299). Shell -c scripts that don't run rm no longer prompt. An rm built at run time inside a script Claude Code can't read prompts only if CLAUDE_CODE_STRICT_INLINE_SHELL_RM_PROMPT=1 is set. [1]
  • Sandbox hardening (v2.1.299). Sandboxed commands can no longer write into a --plugin-dir folder. On macOS, a denied path reached through a symlink is now blocked. Several allowRead/denyRead glob edge cases were also fixed. [1]

Agents & sessions

  • Fork subagents are on by default in more places (v2.1.302). Fork subagents (subagent_type: "fork") are now on by default in claude -p, the Agent SDK, the desktop app and VS Code, as they already were in the terminal. CLAUDE_CODE_FORK_SUBAGENT=0 turns them off. The desktop app and VS Code now always run the main conversation's subagents in the background. As of this writing, the env-vars doc still describes the older interactive-only default. [4][6]
  • Agent view controls (v2.1.299). /effort and /fast in agent view set what new sessions start with. A bare /model, /effort or /fast there opens a picker. [1]
  • Unattended retry cap (v2.1.301). CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS lets unattended retry mode (CLAUDE_CODE_RETRY_WATCHDOG) give up when a usage limit resets too far in the future, instead of waiting for it. [3]
  • Advisor on Claude Platform on AWS (v2.1.300). /advisor is now available there. No advisor runs until you pick one with /advisor, advisorModel or --advisor. CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1 turns it off. [2][6]
  • fable/best alias fallback (v2.1.301). If your organization can't use the newest Fable model, these aliases now retry once on the previous Fable model on the Anthropic API instead of erroring. [3]
  • Transcripts record full requests (v2.1.300). Local session transcripts now also store each API request's system prompt, tools and parameters, so a transcript you share can reproduce a request exactly. Keep this in mind before sharing transcripts. [2]
  • Misc. The % bracket-match motion in vim mode (v2.1.301) [3]; you can watch up to 25 artifacts, up from 10 (v2.1.299) [1]; removal of the no-op --sandbox/--no-sandbox flags on claude remote-control (v2.1.300) [2]; the resume command printed at exit now names the session by its ID (v2.1.299). [1]

Observability, mods & enterprise

  • OpenTelemetry additions. The api_request event now splits cache writes into cache_creation_5m_tokens and cache_creation_1h_tokens, and trace spans carry GenAI semantic-convention attributes such as gen_ai.provider.name (v2.1.300) [2]. tool_decision events gain classifier_verdict and permission_mode, plus classifier_category when OTEL_LOG_TOOL_DETAILS=1 (v2.1.301, fixed in v2.1.302). [3][4]
  • Mods API growth (v2.1.299–301). New in the mods API: $.prompt.media and $.session.identity() for mods installed through managed settings, a virtualText prompt decoration, the prompt.change hook, $.ui.view({ agentId }), multi-line Input rows, and rewriting a workflow agent's prompt/model in agent.spawn. turn.start now also fires for subagent and teammate turns. Managed permission rules, managed hooks and organization MCP tool names are now enforced more strictly against user-installed mods. [1][2][3]
  • Attribution header on gateways (v2.1.299). CLAUDE_CODE_ATTRIBUTION_HEADER=0 removes the attribution block, including in Claude Desktop's Code tab when set in a Claude apps gateway's code policy. [1][6]
  • No redirects on Anthropic connector traffic (v2.1.299). Requests to claude.ai's connector proxy and to Anthropic-hosted MCP servers no longer follow HTTP redirects. Redirects from a connector's own server are unaffected. [1]
  • Claude Design notice (v2.1.302). /design-sync and /design-login now show that standalone Claude Design (claude.ai/design) closes by December 14, 2026. [4]

Tips & Techniques

  • Let idle compaction save you a cache rebuild, or turn it off on purpose. If you often leave a long session idle and come back, keep it on. If you would rather keep the full uncompacted context and pay the cache rebuild, set "idleCompaction": false or raise CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS. [1][6]
  • Use path-only mentions for big files. With CLAUDE_CODE_DISABLE_FILE_MENTIONS=1, @ mentions pass paths only, so Claude reads just the parts it needs instead of loading whole files into context. [1][6]
  • Watch cache spend with the new OTel split. Comparing cache_creation_1h_tokens with cache_creation_5m_tokens shows how much you spend on the pricier one-hour cache writes. [2]
  • Audit auto-mode decisions. Use the classifier_verdict and permission_mode attributes on tool_decision events to tell classifier blocks apart from permission-rule blocks. [3]
  • Re-test hooks that rewrite input. Hooks that return updatedInput with extra or malformed fields may now deny calls they used to allow. [2]

Recommended Default-Config Changes

  • Audit MCP allow rules. Replace bare server rules for servers whose names contain __ (or end in _) with mcp__<whole name>__*. Check agent tools: lists the same way. Rules that relied on the old prefix match no longer auto-approve those tools. [1][7]
  • Set --permission-mode explicitly in CI. Headless runs on third-party providers or with telemetry off now start in default mode. If a pipeline depended on auto mode, pass --permission-mode auto or set permissions.defaultMode. [4]
  • Decide on fork subagents for headless/SDK. If your -p or SDK automations shouldn't spawn forked subagents, set CLAUDE_CODE_FORK_SUBAGENT=0. [4]
  • Choose an idle compaction policy. Set idleCompaction in user or project settings, or use the new /config row, so everyone on the team gets the same behavior. [1][4]
  • Treat transcripts as sensitive. Transcripts now include full system prompts, tools and request parameters, so review them before sharing outside your team. [2]
